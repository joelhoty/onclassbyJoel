🎮 1. I2C 互動式數位通訊模擬實驗室

本模擬器完整還原了 Master (主控單晶片) 與兩組 I2C 周邊裝置 (Device 1: 0x27 LCD、Device 2: 0x68 RTC) 的實體匯流排運作。您可以透過單步執行、速度控制或選擇不同通訊情境，親眼觀察 SDA 與 SCL 的電位變化、位址比對、ACK/NACK 握手反饋以及開汲極晶體開關狀態！

🔎 建議觀察順序（第一次使用請照這 5 步）：
1. 選擇「寫入 Device 1 (0x27)」，按單步前進，先找出 SCL=High 時 SDA 由 High→Low 的 START。
2. 接著數 8 個時脈；只在 SCL 為 High 時讀 SDA，即可得到位址與 R/W 位元。
3. 第 9 個時脈觀察 SDA 控制權交給誰：Slave 拉低就是 ACK，沒人拉低就是 NACK。
4. 每完成 8-bit 資料都會再出現 1-bit ACK；不要把 ACK 誤當成下一個資料位元。
5. 最後找出 SCL=High 時 SDA 由 Low→High 的 STOP，確認匯流排回到 SDA=High、SCL=High。

🧠 2. I2C 核心概念與硬體架構剖析

I2C (Inter-Integrated Circuit) 是由 Philips (現 NXP) 於 1982 年開發的雙線式、半雙工、同步序列通訊匯流排。廣泛應用於微控制器 (MCU) 與各類低速外圍周邊（如感測器、EEPROM、RTC 即時時鐘、LCD 螢幕）之間的板級通訊。

2.1 實體層電路：開汲極 (Open-Drain) 與「線接與 (Wired-AND)」機制

與常見的推挽式 (Push-Pull) GPIO 輸出不同，I2C 匯流排上的所有裝置（無論是 Master 還是 Slave）其 SDA 與 SCL 腳位均採用 開汲極 (Open-Drain / Open-Collector) 架構：

  • 輸出 Low (0)：晶片內部的 N 通道 MOSFET 導通，直接將匯流排線路接地 (GND)，強制拉至低電位 ($0\text{V}$)。
  • 輸出 High (1)：晶片內部的 MOSFET 關斷 (高阻抗浮接狀態 High-Z)，此時匯流排電位完全依賴外部的上拉電阻 (Pull-up Resistor, $R_p$) 將電壓拉高至 $V_{DD}$。
💡 為什麼必須採用 Open-Drain 架構？
1. 避免匯流排短路燒毀：若兩顆晶片同時輸出，一顆輸出 High ($5\text{V}$) 一顆輸出 Low ($0\text{V}$)，推挽結構會瞬間造成電源對地大電流短路；而 Open-Drain 下，只要有一方導通接地，匯流排就呈現 Low，絕不產生短路破壞。
2. 線接與 (Wired-AND) 邏輯：只有當「所有連線的裝置」都關斷 MOSFET 放開匯流排時，線路才會浮高 (High)。任一裝置拉低，全線路即為 Low。這是實現 ACK 應答、時脈伸展 (Clock Stretching) 與多主機仲裁 (Arbitration) 的底層物理基石！
3. 支援多電壓邏輯混用：3.3V 與 5V 裝置只要透過適當的上拉電壓或電平轉換，即可在同一個匯流排上共存。

2.3 完整的 9-Clock 訊框結構與 ACK / NACK 機制

I2C 的資料傳輸以 8 個資料位元 (Byte) + 1 個應答位元 (ACK/NACK) = 9 個時脈脈衝 為一個基本單元：

  1. Byte 1：7 位元設備位址 (A6~A0) + 1 位元讀寫方向 (R/W)
    • $R/\bar{W} = 0$：Master 準備寫入 (Write) 資料給 Slave。
    • $R/\bar{W} = 1$：Master 準備從 Slave 讀取 (Read) 資料。
    • 例如 LCD1602 (位址 0x27 = 0100111b)，寫入時傳送 (0x27 << 1) | 0 = 0x4E；讀取時傳送 (0x27 << 1) | 1 = 0x4F。
  2. 第 9 個時脈：ACK (Acknowledge) / NACK (Not Acknowledge)
    • 在第 8 個時脈結束後，發送端 (Transmitter) 主動釋放 SDA 線（內部 MOSFET 關斷，SDA 浮起）。
    • ACK (確認應答, 0)：若有 Slave 裝置比對到位址匹配或成功接收字節，該 Slave 會在第 9 個時脈期間主動拉低 SDA (Pull Low)。
    • NACK (非應答, 1)：若位址不存在、Slave 忙碌或接收端已不想再讀取下一字節，SDA 保持被上拉電阻拉高 (High)。此時 Master 即可發送 STOP 結束傳輸或進行重試。

2.4 一個 bit 到底怎麼送？從 SCL 與 SDA 的分工開始

🏫 用「老師上課」理解三者關係：
Master 主控端 = 老師 / 指揮者：決定要找哪個 Slave、何時開始、何時結束，並通常負責打拍子。
SCL = 老師的拍手節拍（何時看）：SCL 低時準備答案；SCL 高時接收端正式讀答案。
SDA = 大家共用的白板（答案是什麼）：位址、0/1 資料及 ACK 都寫在這條線上；它是雙向線，發話者會隨交易階段改變。

一句話記憶：Master 用 SCL 告訴大家「何時看」，目前的發送者用 SDA 告訴大家「看到什麼」。
通訊階段SCL 通常由誰控制？SDA 由誰控制？Master 的角色
START、位址、Write 資料MasterMaster打拍子並送出位址或資料
位址或 Write 資料後的 ACKMasterSlave提供第 9 拍，但放開 SDA 等回答
Read 資料MasterSlave提供時脈並讀取 SDA
Read 資料後的 ACK/NACKMasterMaster用 ACK 要下一 Byte，或用 NACK 表示讀完

常見誤解：「Master 控制通訊」不代表 Master 永遠控制 SDA。Master 主要掌握交易流程與 SCL；讀資料或等待 ACK 時，Master 會放開 SDA，讓 Slave 發話。

每一個資料位元都依序走過三個階段：準備 → 取樣 → 完成。Master 產生 SCL 節拍；目前的發送端負責 SDA。

階段SCLSDA 行為接收端要做什麼
① 準備資料LOW發送端要送 0 就拉低；要送 1 就放開，由上拉電阻拉高。先不判讀，等待資料穩定。
② 取樣資料HIGHSDA 必須保持穩定，不可任意切換。讀取 SDA：LOW=0、HIGH=1。
③ 完成此 bit回到 LOW發送端現在才可準備下一個 bit。保存剛才讀到的值。
一句話讀波形：「SCL 低時看資料如何準備，SCL 高時看接收端讀到什麼。」資料由 MSB 先送；每 8 個資料 Clock 後，第 9 個 Clock 專門做 ACK/NACK。第 8 與第 9 Clock 之間，原發送端必須放開 SDA，讓接收端取得 SDA 控制權。

2.5 完整寫入交易：Master 寫資料到 LCD 0x27

S → [0x27 + W] → ACK → [0x08] → ACK → [0x01] → ACK → P

  1. START：Idle 時 SDA、SCL 均為 High；Master 在 SCL=High 時將 SDA 拉低。
  2. Address + W：Master 傳送 0100111 與 W=0，線上 8-bit 位址 Byte 是 (0x27 << 1) | 0 = 0x4E。
  3. Address ACK：所有 Slave 都監聽，但只有位址 0x27 的裝置在第 9 個 Clock 拉低 SDA。
  4. Data + ACK：Master 先送 0x08，Slave 回 ACK；再送 0x01，Slave 再回 ACK。
  5. STOP：Master 在 SCL=High 時讓 SDA 由 Low 回到 High，交易結束。

2.6 完整讀取交易：讀 RTC 0x68 的暫存器 0x00

S → [0x68+W] → ACK → [0x00] → ACK → Sr → [0x68+R] → ACK → [資料] → NACK → P

  1. 第一段用 Write，是為了把 RTC 的內部暫存器指標指定到 0x00，不是要修改秒數。
  2. Master 不送 STOP，而送 Repeated START (Sr)，使整個「指定暫存器後立刻讀取」保持為不可分割的交易。
  3. 第二次定址改用 R=1；線上位址 Byte 為 (0x68 << 1) | 1 = 0xD1。
  4. 位址 ACK 後，資料方向反轉：Slave 控制 SDA 送資料，Master 仍控制 SCL 並負責取樣。
  5. Master 讀完最後一個 Byte 後送 NACK。這裡的 NACK 不是錯誤，而是明確告訴 Slave「不要再送下一個 Byte」，隨後再送 STOP。

2.7 如何根據位址判斷資料由誰接收、誰傳送？

核心規則：7-bit 位址決定「哪個 Slave 被選中」；最後的 R/W 位元決定「接下來資料往哪個方向走」。R/W 永遠以 Master 的角度命名：0 是 Master Write，1 是 Master Read。

START 後第一個 Byte 的結構為：[A6 A5 A4 A3 A2 A1 A0 | R/W]。所有 Slave 都會監聽它，先比較前 7 bit，再檢查最後 1 bit。

位址是否相符R/WACK後續資料方向
否0 或 1該 Slave 不拉低 SDA；若全都不匹配，Master 讀到 NACK該 Slave 不參與，等待下一個 START
是0 (Write)Slave 回 ACKMaster 傳送 → Slave 接收
是1 (Read)Slave 回 ACKSlave 傳送 → Master 接收
  1. 看到 0x4E：0x4E >> 1 = 0x27，所以選中 0x27；0x4E & 1 = 0，所以接下來由 Master 傳資料給 0x27。
  2. 看到 0xD1：0xD1 >> 1 = 0x68，所以選中 0x68；0xD1 & 1 = 1，所以接下來由 0x68 傳資料給 Master。

注意：Slave 回 ACK 表示它接受了「位址與方向」，不代表後續資料內容一定正確。

2.9 Clock Stretching、Arbitration 與 Bus Busy

  • Clock Stretching：Master 放開 SCL 後，尚未準備好的 Slave 可繼續拉低 SCL。Master 必須等到實際 SCL 真的變 High 才能繼續；實作時需確認控制器與函式庫是否支援。
  • 多主機仲裁：某 Master 想送 1（放開 SDA）卻讀到線上為 0，代表另一 Master 正在拉低 SDA；前者輸掉仲裁並立即停止，後者可繼續傳送。
  • Bus Busy：從 START 到 STOP 之間匯流排皆視為忙碌；新交易應等到 SDA=High、SCL=High 的 Idle 狀態。

⚡ 3. 上拉電阻 (Pull-up Resistor) 與 RC 充放電計算器

在實際電路設計中，上拉電阻 $R_p$ 的阻值選擇是一門關鍵的工程權衡 (Trade-off)。若電阻過大，訊號上升時間過慢導致波形失真；若電阻過小，晶片拉低線路時消耗電流過大，可能無法達到合格的低電平電壓 $V_{OL}$。

(包含走線電容、接腳電容，通常約 50~200pF，標準上限 400pF)
最小安全電阻 $R_{p,min}$：966 Ω
(受限於晶片最大灌電流 $I_{OL}=3\text{mA}$)
最大允許電阻 $R_{p,max}$：2.95 kΩ
(受限於最大允許訊號上升時間 $t_r$)
🌟 推薦標準工程選值：2.2 kΩ ~ 4.7 kΩ
📐 物理計算公式推導：
$$R_{p,min} = \frac{V_{DD} - V_{OL,max}}{I_{OL}} \quad \text{其中 } V_{OL,max}=0.4\text{V}, I_{OL}=3\text{mA}$$ $$R_{p,max} = \frac{t_r}{0.8473 \times C_b} \quad \text{依據 RC 電路從 } 0.3V_{DD} \text{ 充電至 } 0.7V_{DD} \text{ 所需時間}$$

💻 5. 硬體與軟體程式碼實作 (Arduino C++ & Bit-Banging)

在嵌入式系統中，我們通常使用硬體周邊單元 (如 Arduino Wire.h)；但在某些不具備硬體 I2C 模組的晶片或引腳上，亦可使用普通 GPIO 進行 軟體模擬 I2C (Bit-Banging)。

範例 1：Arduino Uno 同時控制雙周邊 (LCD 0x27 與 RTC 0x68)

在此範例中，Arduino Uno 透過 A4 (SDA) 與 A5 (SCL) 同步向 0x27 (LCD1602) 寫入歡迎文字，並從 0x68 (DS3231) 讀取當前時間：

📄 Arduino_Dual_I2C_Devices.ino 
#include <Wire.h>

// 定義兩台 I2C 設備的 7-bit 位址
#define LCD_ADDR  0x27  // 周邊 1: PCF8574 LCD 擴展晶片位址
#define RTC_ADDR  0x68  // 周邊 2: DS3231 / MPU6050 位址

// BCD 碼轉十進位函式 (DS3231 內部秒/分/時均以 BCD 格式儲存)
byte bcdToDec(byte val) {
    return ((val / 16 * 10) + (val % 16));
}

void setup() {
    Serial.begin(115200);
    while (!Serial); // 等待序列埠監視器開啟

    // 初始化 I2C 主機模式 (Uno 預設: A4=SDA, A5=SCL)
    Wire.begin();
    Wire.setClock(100000); // 設定為標準模式 100 kHz

    Serial.println(F("========================================"));
    Serial.println(F("[I2C Master] 雙裝置 (0x27, 0x68) 通訊初始化完成"));
    Serial.println(F("========================================"));

    // 1. 寫入周邊 1 (LCD 0x27)：送出初始化控制背光指令
    Wire.beginTransmission(LCD_ADDR);
    Wire.write(0x08); // 寫入資料字節 1 (控制暫存器，開啟背光)
    Wire.write(0x01); // 寫入資料字節 2 (清除顯示器指令)
    byte errorLcd = Wire.endTransmission(); // 產生 STOP 條件並接收 ACK/NACK

    if (errorLcd == 0) {
        Serial.println(F("[SUCCESS] 成功與 0x27 (LCD) 握手並寫入控制字節 (ACK 回應)"));
    } else {
        Serial.print(F("[ERROR] 0x27 (LCD) 無法連線，錯誤代碼: "));
        Serial.println(errorLcd); // 2: 位址收到 NACK, 3: 資料收到 NACK
    }
}

void loop() {
    // 2. 讀取周邊 2 (RTC 0x68)：讀取即時時鐘之「秒」暫存器
    // 步驟 2.1: 先發送寫入模式，指定要讀取的暫存器位址為 0x00 (秒數暫存器)
    Wire.beginTransmission(RTC_ADDR);
    Wire.write(0x00); // 暫存器指標指向 0x00 (Seconds)
    byte errorRtc = Wire.endTransmission(false); // 傳送 Repeated START (不放開匯流排)

    if (errorRtc == 0) {
        // 步驟 2.2: 切換為讀取模式，向 0x68 請求讀取 1 個 Byte
        Wire.requestFrom(RTC_ADDR, 1);
        if (Wire.available()) {
            byte rawSeconds = Wire.read(); // 讀取資料並自動在最後一個 byte 回應 NACK + STOP
            byte seconds = bcdToDec(rawSeconds & 0x7F);
            Serial.print(F("[RTC 0x68 讀取成功] 當前秒數: "));
            Serial.println(seconds);
        }
    } else {
        Serial.println(F("[ERROR] 0x68 (RTC) 設備未回應 ACK"));
    }

    delay(1000); // 每秒讀取一次
}

範例 2：純 GPIO 軟體模擬 I2C (Bit-Banging 核心演算法剖析)

透過精準控制引腳的高低電位與輸入/輸出狀態，可手動實現 I2C 通訊時序：

📄 I2C_BitBang_Core.cpp 
// 模擬 Open-Drain 行為：
// 輸出 0: pinMode 為 OUTPUT, digitalWrite 為 LOW (強制拉地)
// 輸出 1: pinMode 為 INPUT (高阻態 High-Z, 藉由外部上拉電阻浮至 5V)
void sda_low(int pinSda)  { pinMode(pinSda, OUTPUT); digitalWrite(pinSda, LOW); }
void sda_high(int pinSda) { pinMode(pinSda, INPUT); }
void scl_low(int pinScl)  { pinMode(pinScl, OUTPUT); digitalWrite(pinScl, LOW); }
void scl_high(int pinScl) { pinMode(pinScl, INPUT); }

// 產生 START 條件：當 SCL 為 High 時，SDA 由 High 降為 Low
void i2c_start(int pinSda, int pinScl) {
    sda_high(pinSda);
    scl_high(pinScl);
    delayMicroseconds(5);
    sda_low(pinSda);   // SDA 下降沿
    delayMicroseconds(5);
    scl_low(pinScl);   // 鎖定時脈進入低電位，準備送出資料位元
}

// 產生 STOP 條件：當 SCL 為 High 時，SDA 由 Low 升為 High
void i2c_stop(int pinSda, int pinScl) {
    sda_low(pinSda);
    delayMicroseconds(5);
    scl_high(pinScl);
    delayMicroseconds(5);
    sda_high(pinSda);  // SDA 上升沿
    delayMicroseconds(5);
}

// 送出 1 個位元組並接收 Slave 的 ACK 訊號 (回傳 true 代表收到 ACK)
bool i2c_write_byte(int pinSda, int pinScl, uint8_t byteData) {
    // 依序由最高位元 (MSB, Bit 7) 送至最低位元 (LSB, Bit 0)
    for (int i = 7; i >= 0; i--) {
        if (byteData & (1 << i)) {
            sda_high(pinSda);
        } else {
            sda_low(pinSda);
        }
        delayMicroseconds(5);
        scl_high(pinScl); // 接收端在此上升沿與 High 期間進行採樣
        delayMicroseconds(5);
        scl_low(pinScl);
    }

    // 第 9 個時脈：釋放 SDA，讀取周邊裝置拉低的 ACK
    sda_high(pinSda); // 釋放 SDA 線
    delayMicroseconds(5);
    scl_high(pinScl);
    delayMicroseconds(5);
    bool ack = (digitalRead(pinSda) == LOW); // 0 代表 Slave 回應 ACK
    scl_low(pinScl);
    return ack;
}

6.1 常用板級串列通訊協定全方位對比 (I2C vs SPI vs UART)

比較維度 I2C (雙線匯流排) SPI (串列周邊介面) UART (非同步收發器)
訊號線數 2 線 (SDA, SCL) 4 線+ (MOSI, MISO, SCK, CS/SS) 2 線 (TX, RX)
傳輸模式 半雙工 (Half-Duplex) 全雙工 (Full-Duplex) 全雙工 (Full-Duplex)
典型傳輸速率 100 kHz ~ 1 MHz (高速可達 3.4MHz) 10 MHz ~ 80 MHz+ (極高速) 9600 bps ~ 1 Mbps (一般)
定址能力與擴充 軟體定址 (7-bit 可掛高達 128 個) 硬體片選 (每個 Slave 需一條 CS 線) 點對點 (Point-to-Point)
硬體開銷與走線 極低 (僅需 2 個 Pin + 上拉電阻) 高 (腳位隨裝置數量線性暴增) 極低 (但僅限一對一通訊)
通訊握手機制 有 (每 8 位元均具備 ACK/NACK 握手) 無 (Master 盲發盲收) 無 (需軟體通訊層協議實作)

6.2 常見邊界問題與除錯實務 (Troubleshooting & Best Practices)

⚠️ 1. 匯流排鎖死 (Bus Hang / Bus Lockup)：SDA 被 Slave 永久拉低怎麼辦？
當 Master 在讀取 Slave 資料中途發生異常重置 (MCU Reset 或死當) 時，Slave 可能正停在「拉低 SDA 輸出 0 或 ACK」的中途狀態。由於 Master 重開機後 SCL 處於閒置高電位，Slave 會永遠等待 SCL 下一個脈衝而持續拉死 SDA，導致整個匯流排癱瘓！
解決方案（9-Clock Reset 復原程序）：
Master 在開機初始化時，若檢測到 SDA 異常處於 Low，切換為 GPIO 手動送出 9 個連續的 SCL 時脈脈衝。這會強迫 Slave 完成當前 Byte 的傳輸並釋放 SDA，最後 Master 再發出一個 STOP 條件，即可完美重置匯流排！
🧩 2. 設備位址衝突怎麼解決？
若在同一系統上需要連接兩顆相同型號且不可改位址的感測器（例如兩台預設固定 0x27 的液晶面板）：
1. 硬體切換位址腳 (Address Pins)：許多晶片提供 A0, A1, A2 針腳，接 VCC 或 GND 可設定 8 組不同位址。
2. 使用 I2C 多工器晶片 (如 TCA9548A)：Master 僅需連接 TCA9548A，透過軟體切換 8 個獨立的 I2C 通道 (Channel 0~7)，即可無縫掛載相同位址的周邊裝置。
