🚀 二、六大核心階段 SOP 深度解析

🔌 階段一：硬體先行與實體拍照檢核 (Hardware First & Visual Audit)

核心理念：軟體必須建立在堅若磐石的實體電氣連接上。絕不在接線未定時空想代碼。

  • 電源軌規劃：利用麵包板頂端紅藍電源軌分配 5V 與 GND，避免單一 Arduino 針腳插拔鬆脫。
  • 訊號分類：I2C 設備固定走 A4/A5，數位感測器指定單一 GPIO（如 Pin 7）。
  • 多視角留存：拍照記錄線色與引腳孔位（如 2026-10-20-143026.jpg 與 2026-10-20-153116.jpg），方便未來比對。
🧪 階段二：官方範例與單元隔離測試 (Unit Testing via Standard Examples)

核心理念：「不要同時測試兩件未知的事物」。先分別驗證個別零件是否完好。

  • 安裝官方認證庫：至 Library Manager 安裝 LiquidCrystal_I2C 與 DHT sensor library。
  • 隔離測試 LCD 1602：跑 HelloWorld.ino，確認背光、對比度與 0x27 位址正常。
  • 隔離測試 DHT11：跑 DHT_Unified_Sensor.ino，開 Serial Monitor 捏住感測器看數值是否攀升。
🔍 階段三：訊號監測與故障診斷排除 (Signal Monitoring & Diagnostic Debugging)

核心理念：以科學手段觀察現象、推理本質，不盲目亂猜。

  • 條紋雜訊排除（如 2026-10-20-153902.jpg）：發現更換程式未帶 Wire.h 會留存隨機位元，以雙重 lcd.init() 軟硬體複位解決。
  • 位址探測：遇到螢幕無反應時，以 I2C Scanner 秒速測出是否為 0x3F。
  • 硬體微調：以螺絲起子微調藍色十字電位器達到最佳對比。
🧩 階段四：漸進式模組整併與時序調度 (Incremental Integration & Scheduling)

核心理念：以最小增量整併代碼，解決總線與週期的時序衝突。

  • 統一標頭檔與物件實例：將 Wire.h 與 DHT.h 納入同一 sketch。
  • 時序協同：嚴格遵守 DHT11 最小 1.5 秒物理採樣週期，避免感測器過熱失真。
✨ 階段五：使用者介面拋光與工程細節優化 (UI Polish & Best Practices)

核心理念：追求專業工程標準：防閃爍、字元編碼對齊與防禦性容錯。

  • 防閃爍技巧：以「固定長度空格覆寫」取代 lcd.clear()，保證畫面平順不狂閃。
  • 度數符號：使用 lcd.write(223) 輸出 HD44780 內建 ASCII 223 圓圈「°」，拒絕亂碼。
  • 容錯機制：加入 isnan() 判斷，避免感測器脫落時程式崩潰。
📚 階段六：多模態文檔歸檔與版本控制 (Multimodal Archiving & Git Push)

核心理念：「能被完整複現的實驗，才是成功的專案」。

  • 多模態同步產出：同時產出 Markdown 與高質感 HTML（含 PDF 匯出、代碼複製按鈕）。
  • 索引自動維護：自動更新 INDEX.md 與 index.html。
  • Git 雲端備份：Commit 並 Push 至 GitHub 儲存庫。

🛡️ 三、Arduino 常見工程地雷與防禦性編程 Checklist

檢核項目 常見錯誤現象 正確防禦做法
I2C 匯流排 換程式後 LCD 螢幕留下垂直條紋雜訊 必引用 <Wire.h> 並在 setup() 呼叫兩次 lcd.init() 雙重複位。
感測器採樣率 DHT11 數值過高或頻繁回傳 NaN 錯誤 採樣間隔嚴格遵守物理規格（DHT11 至少 1.5 秒，DHT22 至少 2 秒）。
螢幕文字刷新 畫面每次數值更新時全螢幕黑白狂閃跳動 嚴禁在 loop() 頻繁使用 lcd.clear()，改用空白字元定長覆寫。
特殊符號輸出 印出 ° 變成片假名或亂碼 勿直接在字串中鍵入 °，改用 lcd.write(223) 輸出內建字型碼。
序列埠通訊 序列埠視窗完全空白或充滿問號亂碼 確認程式碼 Serial.begin(9600) 與 IDE 監視器右下角鮑率完全一致。
