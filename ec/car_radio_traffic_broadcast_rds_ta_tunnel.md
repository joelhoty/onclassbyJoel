## TL;DR

- **雪山隧道**的插播，是高公局的 **FM 全頻道隧道廣播系統**：外部電台在隧道內收不到，由系統轉播進來；行控中心需要時，可以在**所有轉播頻道**同時插播路況與應變指示。收聽條件：**車上音響開著，而且在 FM 收音機模式**。「全頻道」是否也包含沒有電台的空白頻率，目前沒有定論；業界同類系統（例如日本國土交通省的規格）的「全頻道」，指的是**所有轉播頻道**。
- **RDS-TA** 是另一種機制：在類比 FM 訊號裡夾帶 1 bit 的「正在播路況」旗標，車機收到後**自動把音源切到收音機**。這需要電台送旗標、車機支援並開啟 TA，而且車廠的韌體允許 TA 打斷目前的音源。
- 用 **CarPlay、藍牙**聽音樂時，**隧道插播一定聽不到**；RDS-TA 則要看車廠設計。唯一不靠車上音響的，是**手機的災防告警（PWS）**。

## 一、技術總覽

| 技術 | 一句話說明 | 自動切換音源？ | 常見地區 |
|---|---|---|---|
| **隧道廣播插播** | 隧道內轉播外部電台，必要時由行控中心蓋台插播 | 否，蓋掉的是廣播內容 | 台灣雪山隧道（高公局稱「全台唯一」） |
| **RDS-TA／EON** | FM 訊號夾帶 TA 旗標，車機自動切到路況播報 | **是** | 歐洲普遍；台灣電台使用狀況不明 |
| **HAR（Highway Advisory Radio）** | 路邊低功率發射器，重複播放當地路況 | 否，要自己轉到指定頻率 | 美國；日本（ハイウェイラジオ，1620 kHz） |
| **PWS 災防告警（細胞廣播）** | 由基地台推送到手機 | 不經過收音機 | 台灣與多數國家 |
| 非刻意現象 | 同頻強訊號壓過（capture effect）、互調干擾 | — | 不限地區 |

### 如何分辨

| 觀察 | 最可能 |
|---|---|
| 在隧道內，FM 轉到哪一台都是同一段廣播 | 隧道插播 |
| 車機顯示 TA／Traffic，聽 CD 或 USB 時也被切斷 | RDS-TA |
| 路邊有「路況廣播請轉 XXX kHz」的告示 | HAR |
| 聲音從手機發出，伴隨刺耳的警報音 | PWS |
| 內容是一般節目，而且斷斷續續 | 訊號壓過或干擾 |

## 二、運作原理

### 2.1 雪山隧道 FM 全頻道廣播系統（已查證）

**機制**
1. 雪山隧道全長約 12.9 km，外部的廣播訊號進不去。
2. 系統把外部 FM 電台**整批轉播**進隧道。網友用 SDR 實測，隧道內看得到大量強度相近的電台訊號，代表這些訊號是轉播進來的。
3. 平時播的內容：高公局 FAQ（見來源說明）寫的是「隧道行車安全、路況及緊急應變事項」；TVBS 報導則提到速限提醒，以及針對逗留、龜速車的播報，甚至會唸出車號。
4. 緊急時，**行控中心人員插播**路況與應變指示（熄火、留在車內或棄車疏散）。播報者是高公局人員輪流擔任。

**「全頻道」的意思**
- 高公局 FAQ（摘要引文）寫：「隧道內透過FM所有頻道播放……用路人只要打開收音機FM頻道均接收該廣播」。
- 承包廠商寫：「全台灣唯一全頻道調頻FM廣播」。
- 可以確定的是：插播**不限於某一家電台**，聽任何一個有轉播的 FM 台都會聽到。
- 不能確定的是：**沒有電台的空白頻率**是否也有插播。日本國土交通省同類設備的規格寫「全チャンネル一斉に」插播（見 2.1.1），這裡的「全チャンネル」指的是**所有轉播頻道**，不是整個波段的每一個頻點。高公局的「FM所有頻道」可能也是同樣的意思。

**硬體**（廠商一手資料）
- FM 調頻發射機
- FM 天線
- FM 光電轉換器
- FM 全頻道射頻信號放大器
- FM 全頻道 Combiner

#### 2.1.1 可能的系統作法（推論）

> 本節是**推論**。雪隧的實際設計沒有公開資料；推論依據是廠商的設備清單，以及國外同類系統的公開規格（S006–S008）。

**參照一：日本國土交通省的規格（最具體的公開資料）**

日本國土交通省的《トンネル内ラジオ再放送設備（割込み有り）機器仕様書》（2021 年 3 月）寫明的架構如下：

```
洞外 FM 接收天線
   ↓
FM 接收部（每一個電台各一組，最多 12 個頻道）→ 輸出 AF（聲音）或 IF（中頻）
   ↓
FM 放送切換部 ←── 插播來源：麥克風／預錄語音 → FM 調變部（調成 10.7 MHz IF）
   │  平時：把各電台的訊號分送到各自的送信部
   │  插播：把「插播 IF」同時分送到所有送信部
   ↓
FM 送信部（每個頻道一台，轉回原本的頻率）
   ↓
FM 出力混合部（Combiner：5 波以下一種型號，6 波以上另一種）
   ↓
LCX 洩漏同軸電纜（與管理用無線電共用）→ 隧道內
```

重點：
- **逐台處理**：每個電台有自己的接收與發射通道，不是整個波段一起放大。
- **切換點在 IF 或 AF 層**：插播聲音只調變一次（10.7 MHz），再複製給所有頻道的送信部，所以能做到「全チャンネル一斉に」插播。
- **只覆蓋轉播頻道**：送信部只發射指定的頻率，空白頻率不會有訊號。
- **轉播方式有兩種**，由個案規格決定：AF 中繼（解調成聲音再重新調變）與 IF 中繼（不解調，保留立體聲與文字多重資料）。
- **插播優先順序**：①隧道內手動通報連動的緊急插播 ②插播用麥克風 ③插播終端設備。上、下行隧道可以分開插播。
- 插播調變部的聲音頻寬只有 200 Hz–7.5 kHz，也就是**單聲道、以人聲為主**。

**參照二：PIARC 道路隧道手冊**

PIARC（世界道路協會）把這類功能稱為 **Voice Break-In（VBI）**：
- 構成：洞外接收天線 → 機房接收與發射設備 → VBI 設備 → 洩漏電纜**或**天線。
- 插播可以是預錄或現場播報。
- 要跟隧道的揚聲器廣播（PA）錯開，不同時播出。

**雪隧可能的架構**

廠商清單出現「全頻道射頻信號放大器」和「全頻道 Combiner」，而不是日本規格那樣的「每台一組接收部」。因此雪隧可能跟日本的做法不同。依證據推測有以下幾種可能：

| 作法 | 平時轉播 | 插播 | 空白頻率有插播嗎 | 與證據的吻合度 |
|---|---|---|---|---|
| **① 逐台處理（日本式）** | 每一台各自接收、各自發射，再由 Combiner 合成 | 所有頻道的輸入同時切到插播來源 | 沒有 | **中高**：「發射機＋Combiner」符合；網友實測「各台強度差不多」也符合，因為每台發射功率可以設成一樣 |
| **② 寬頻直通＋本地發射機** | 洞外整個 FM 波段經「全頻道射頻放大器」直接放大轉播 | 切斷寬頻訊號，改由數台本地發射機在主要電台頻率上播出，經 Combiner 合成 | 沒有 | **中高**：「全頻道放大器＋發射機＋Combiner」三者都用得上 |
| **③ 數位寬頻處理** | 整個波段數位化，經光纖傳送後還原 | 由 DSP 在多個頻率同時合成相同內容 | 視設計而定 | 中：中國大陸同類產品有這類說法，但沒有一手資料 |
| **④ 疊加壓台** | 寬頻直通 | 不切斷，直接用更強的訊號同頻發射，靠 capture effect 蓋過原台 | 視設計而定 | **低**：強度差不夠時會變成混音，不適合緊急廣播 |

**分配層（兩種做法都可能）**
- 「FM 光電轉換器」代表至少有一段是**用光纖傳 RF**（RF over fiber）。12.9 km 如果全部用同軸電纜，損耗太大，所以常見做法是用光纖把訊號送到隧道內各段，再還原、放大。
- 最後一段的輻射方式，可能是天線（廠商清單列的是「FM 天線」），也可能是 LCX 洩漏電纜（日本規格與 PIARC 的標準做法）。**目前沒有證據能確定雪隧用哪一種。**

**可以自己驗證的方法**

| 實驗 | 結果 → 傾向 |
|---|---|
| 插播時轉到**空白頻率** | 聽得到 → ③ 或 ④；聽不到 → ① 或 ② |
| 在隧道內看車機的 **RDS 台名**，或聽**立體聲**指示燈 | 消失 → 有「解調再調變」（① 的 AF 中繼）；保留 → 寬頻直通（②）或 IF 中繼（①） |
| 跟洞外**同一台**比較有沒有**延遲** | 有明顯延遲 → 有數位處理（③） |
| 用 SDR 看插播時的頻譜 | 空白頻率出現新的載波 → ③ |
| 插播時的**音質** | 窄頻、單聲道 → 與日本規格的插播調變部相似 |

### 2.2 RDS：類比 FM 上的數位資料通道

**訊號層：FM MPX 頻譜**

```
頻率(kHz)  0 ────── 15   19   23 ────── 53   57
           [ L+R 單聲道 ] 導頻 [ L−R 立體聲差 ] [RDS]
```

| 位置 | 內容 |
|---|---|
| 0–15 kHz | 左右聲道相加（單聲道收音機只聽這段） |
| 19 kHz | 導頻，代表這台是立體聲 |
| 23–53 kHz | 左右聲道相減，用來還原立體聲 |
| **57 kHz** | **RDS 資料副載波**（導頻的 3 倍，方便同步） |

- 57 kHz 高於人耳的聽覺範圍（約 20 kHz），所以不會干擾收聽。
- 傳輸速率只有 **1187.5 bit/s**，以 BPSK 調變。
- 設計重點是**向後相容**：舊收音機照常播放，新收音機多了一條資料通道。

**資料層：資料組與欄位**

每一組資料有 104 bits，由 4 個區塊組成；每個區塊 26 bits，其中 16 bits 是資料、10 bits 是錯誤檢查碼。

| 欄位 | 大小 | 內容 |
|---|---|---|
| PI | 16 bits | 電台身分碼，換頻率也不變 |
| **TP** | 1 bit | 本台**提供**路況服務（每一組都有） |
| **TA** | 1 bit | 本台**現在正在**播路況（主要在 0A／0B 組，每秒重複多次） |
| PTY | 5 bits | 節目類型 |
| PS | 8 個字元 | 螢幕上顯示的台名 |
| RT | 最多 64 個字元 | 滾動文字，例如歌名 |
| AF | 頻率清單 | 同一電台的其他發射頻率 |
| CT | 日期時間 | 車機自動校時 |
| EON | 別台資訊 | 其他電台的 PI、頻率、TA 狀態 |
| TMC | 結構化編碼 | 以資料形式傳送的路況事件 |

**車機層：處理路徑與決策**

```
天線 → 調諧器(FM解調) → MPX → 57kHz濾波 → RDS解碼晶片 → 微控制器(MCU)
                        └→ 音訊路徑 ──────────────────→ 音源切換器 → 喇叭
```

```
使用者開啟 TA 功能
  └→ 目前調諧的電台 TP = 1 嗎？
       否 → 顯示「No TP」或自動搜尋有 TP 的電台
       是 → 持續監看 TA 旗標
             TA 從 0 變 1：暫停或靜音目前音源 → 音訊切到收音機 → 音量調到 TA 音量
             TA 從 1 變 0：恢復原本的音源和音量
```

- 聽 CD、USB、藍牙時，調諧器仍在**背景**收聽 TP 電台，只是聲音沒送到喇叭。
- **EON**：A 台透過 RDS 通知「B 台現在 TA = 1」，車機就暫時跳到 B 台，播完再跳回 A 台。雙調諧器的車機可以用第二個調諧器在背景追蹤其他電台。
- **EON 支不支援，主要看韌體，不是晶片**：RDS 解碼晶片通常只負責把 57 kHz 的訊號解成資料區塊，並做錯誤檢查。「讀取 14A／14B 組 → 判斷別台 TA → 跳台 → 跳回」這整套邏輯，由車機 MCU 的韌體實作。單調諧器也能做 EON，因為別台的資訊是透過目前這一台的訊號送來的；雙調諧器只是讓跳台更順、不中斷。另外，前提仍然是**電台端有送 EON 資料**。

### 2.3 TA 與 TMC 的差別

| | TA | TMC |
|---|---|---|
| 內容 | 1 bit 開關（「播音中」燈號） | 事件碼、地點碼、方向、範圍 |
| 誰使用 | 音響，拿來切換聲音 | 導航，拿來畫地圖、規劃路線 |
| 路況資訊在哪裡 | 在播報員的**聲音**裡 | 在**資料**本身 |

### 2.4 技術定位：類比與數位混合

| 層次 | 性質 |
|---|---|
| RDS 資料本身 | 數位（有封包和錯誤檢查碼） |
| 資料怎麼掛上去 | 數位調變（BPSK 調變到 57 kHz） |
| 整包訊號怎麼發射 | 類比 FM |
| 聲音 | 類比 |

對照完整的數位廣播：**DAB／DAB+** 的聲音本身就是數位編碼，資料容量大，但舊收音機不能收聽；**HD Radio** 則在類比 FM 旁加上數位訊號。

## 三、硬體與使用條件

### 3.1 各技術的前提

| 技術 | 廣播端 | 車機端 | 使用者要做的事 |
|---|---|---|---|
| 雪山隧道插播 | 高公局的隧道轉播與插播系統 | 任何 FM 收音機 | 音響開著，**切到 FM 模式**（官方建議收聽警廣） |
| RDS-TA | 電台必須**送 TP／TA 旗標** | 支援 RDS-TA，韌體允許 TA 打斷目前音源 | 音響開著，**開啟 TA 功能**（很多車預設是關的） |
| HAR | 路邊發射器 | 任何 AM／FM 收音機 | 看到告示後自己轉台 |
| PWS | 電信業者的基地台 | 不需要車上設備 | 手機開機、有訊號 |

**RDS-TA 的三個條件缺一不可**：電台送旗標、車機支援並開啟 TA、車廠的音訊優先政策允許打斷。
- 「能不能打斷」不是 MCU 做不做得到的問題，MCU 幾乎都能切換音源。
- 真正的差別在**車廠韌體定義的音訊優先順序**。

### 3.2 用 CarPlay 或藍牙聽音樂時

| 技術 | 聽得到嗎？ | 原因 |
|---|---|---|
| 雪山隧道插播 | **聽不到** | 音樂是手機傳來的數位音訊，完全不經過收音機 |
| RDS-TA | **看車廠** | CarPlay 設計上由車機保有音訊的最終控制權；TA 能不能打斷 CarPlay，由車廠決定 |
| PWS | **收得到** | 手機自己收；警報聲從手機還是車上喇叭發出，會因 iOS 版本和車機而不同（未驗證） |

## 四、實際差別總表

| 比較項目 | 雪山隧道插播 | RDS-TA |
|---|---|---|
| 做法 | 直接換掉廣播的**聲音內容** | 傳送**旗標**，由車機決定是否切換 |
| 覆蓋範圍 | 隧道內所有 FM 轉播頻道（是否包含空白頻率未定） | 送 TA 旗標的電台服務範圍 |
| 需要車機配合嗎 | 不用，任何 FM 收音機都行 | 需要支援 RDS-TA，而且要開啟 |
| 能不能打斷非收音機音源 | 不能 | 可以，但要看車廠 |
| 誰決定插播 | 高公局行控中心 | 電台播控人員（按下 TA） |
| 台灣現況 | 已查證在運作 | 不明 |

**實務建議**：進雪山隧道前，把音源從 CarPlay 或藍牙**切回 FM**。

## 五、討論中的釐清與更正

| 原本的說法或問題 | 更正 |
|---|---|
| 雪隧只在「有轉播的特定頻道」插播（查證前的判斷） | 第一次查證後，我改口說是「整個 FM 波段」；第二次查證發現這個改口**過度解讀**了。日本規格的「全チャンネル」指的是所有轉播頻道，所以高公局的「FM所有頻道」可能也是同樣的意思。**目前的結論是：所有轉播頻道都會插播；空白頻率未定** |
| 雪隧用洩漏電纜轉播 | **沒有證據**。廠商清單寫的是「FM 天線」；LCX 洩漏電纜是日本規格和 PIARC 的標準做法，但雪隧的情況沒有證實 |
| EON 要看晶片支不支援 | 主要看**韌體**。晶片只負責解碼，跳台邏輯在 MCU 韌體；另外還要電台端有送 EON 資料 |
| 隧道入口告示會寫建議頻率 | **沒有查到**。官方建議是收聽警廣 |
| TA 是「低頻訊號」 | 不對，是**低速率**。57 kHz 副載波本身的頻率並不低，速率只有 1187.5 bit/s |
| 重點在「MCU 能不能中斷」 | MCU 都做得到，真正的差別在**車廠的音訊優先政策** |
| RDS-TA 只要看車機 | 還要**電台端送旗標** |
| 用 AirPlay 聽音樂 | 車上通常是 **CarPlay**；AirPlay 主要用在 HomePod、Apple TV |
| RDS 是無線數位傳輸 | 比較精確的說法是「**類比 FM 上附掛的數位資料通道**」 |
