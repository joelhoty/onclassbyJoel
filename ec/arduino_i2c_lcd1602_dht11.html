📖 系統導論與專題概述 (System Overview)

本專題以 Arduino Uno R3 微控制器為核心，結合 DHT11 數位溫濕度感測模組 與 I2C 介面 LCD 1602 液晶顯示模組，實現一套即時環境溫濕度監測與數值視覺化系統。

在嵌入式物聯網 (IoT) 與環境監控系統開發中，溫濕度數據為最基礎且常見的監測項目。本設計解決了傳統微控制器感測專案中的四大核心工程痛點：

  • 極簡化引腳佔用 (I2C 匯流排優化)：傳統 LCD 1602 採用平行資料介面需消耗 6~10 根 GPIO 引腳；本系統採用基於 PCF8574 晶片的 I2C 背板，僅需 SDA (A4) 與 SCL (A5) 兩條匯流排線即可驅動。
  • 單匯流排時序協調 (Single-Bus Timing)：DHT11 採用專屬的單線雙向協定，仰賴微秒 ($\mu\text{s}$) 等級之脈衝寬度調變進行 40-Bit 封包接收與校驗和檢查。
  • Adafruit Unified Sensor 架構：採用業界標準的 Adafruit_Sensor 與 DHT_U 函式庫，自動讀取感測器硬體規格與最小取樣週期（sensor.min_delay）。
  • 模組化五步驟工程思維：先確認硬體接線，依序安裝程式庫並進行獨立模組單元測試，最終透過 AI 協同完成整合，兼顧除錯效率與程式碼品質。

🔬 一、核心概念剖析 (Core Concepts)

1.1 I2C 序列通訊與 PCF8574 擴展架構

I2C（Inter-Integrated Circuit）是半雙工、同步序列匯流排，僅依靠 SDA (資料) 與 SCL (時脈) 兩根線路實現多主多從通訊。

  • 開漏極 (Open-Drain) 與線與 (Wired-AND)：SDA 與 SCL 引腳皆為開漏極架構，需依靠匯流排上拉電阻（通常為 $4.7\text{k}\Omega$）將電平拉至 $+5\text{V}$。當任何設備拉低電平時，匯流排呈現 LOW，從物理層面消除了短路燒毀的風險。
  • PCF8574 晶片位址解碼： PCF8574 的 7-bit 設備位址由高位固定碼與低三位硬體引腳 $A_2, A_1, A_0$ 決定： $$\text{PCF8574 Address} = [0, 1, 0, 0, A_2, A_1, A_0]_2$$ 若轉接板的位址焊點未短接（內部預設拉高），則位址為 $[0, 1, 0, 0, 1, 1, 1]_2 = 0x27$；若焊點全短接至 GND，則位址變更為 $[0, 1, 0, 0, 0, 0, 0]_2 = 0x20$。
  • 4-Bit 驅動模式：PCF8574 的 8 根 I/O 輸出腳分別連接 LCD 1602 的 $RS, RW, EN$、背光控制電晶體與 4 根資料線 ($D_4 \sim D_7$)。每個 Byte 字元或指令分兩次（先高 4 位，再低 4 位）傳輸。

1. 濕度感測物理機制：高分子電解質阻抗變化 (Resistive Polymer Humidity Sensing)

DHT11 採用高分子薄膜濕敏電阻作為感濕核心：

  • 水分子吸附與解離：薄膜表面含有豐富的親水性官能基。當空氣相對濕度（$\%\text{RH}$）上升時，水分子經毛細孔被吸附進入聚合物網絡，促使親水官能基解離出高活動度的水合氫離子（$\text{H}_3\text{O}^+$）。
  • Grotthuss 質子傳遞導電機制：水分子越多，氫鍵網絡傳遞質子越順暢，材料導電度急遽提高，阻抗呈對數級下降： $$\log(R_H) \propto -k \cdot (\%\text{RH})$$ 低濕（$20\%\ \text{RH}$）時阻抗達數 $\text{M}\Omega$；高濕（$90\%\ \text{RH}$）時劇降至數 $\text{k}\Omega$。
  • 解吸附弛豫延遲 (Relaxation Time)：水分子脫附逸散需要熱平衡時間（物理響應約需數秒），因此無法即時瞬間反映急遽的濕度突變。

2. 溫度感測物理機制：NTC 負溫度係數熱敏電阻 (NTC Thermistor)

測溫採用過渡金屬氧化物（$\text{Mn}, \text{Co}, \text{Ni}$）高溫燒結而成的半導體陶瓷：

  • 半導體載子熱激發：溫度升高時，熱能激發價帶電子躍遷至導帶，自由電子與電洞濃度呈指數增加，電阻急劇下降。
  • 數學物理模型（Steinhart-Hart 與 $\beta$ 參數公式）： $$\frac{1}{T} = A + B \ln(R) + C (\ln(R))^3$$ 在常用工作範圍內，常簡化為 $\beta$ 參數模型： $$R(T) = R_0 \cdot \exp\left[ \beta \left( \frac{1}{T} - \frac{1}{T_0} \right) \right] \quad \Longleftrightarrow \quad T = \frac{1}{\frac{1}{T_0} + \frac{1}{\beta} \ln\left(\frac{R}{R_0}\right)}$$ 其中 $T_0 = 298.15\text{K}\ (25^\circ\text{C})$，$R_0$ 為標稱阻值，$\beta$ 為材料常數。

3. 內部 8-Bit MCU 訊號調理、OTP 校準與溫度補償

  • OTP 出廠標定校準 (Calibration)：DHT 晶片在出廠前均置於精密標準溫濕度校驗艙，標定多點數值並將補償係數永久燒錄於 OTP 唯讀記憶體。
  • 即時交叉溫度補償：相對濕度極度依賴環境飽和水蒸氣壓。內部 MCU 在讀取感濕阻抗的同時，會即刻調用 NTC 溫度數值進行非線性動態溫度交叉補償，大幅降低溫漂誤差。

4. 單匯流排 40-Bit 脈衝寬度調變 (PWM) 數位協定時序

  • 主控端喚醒 (Start Signal)：Arduino 將 Pin 8 拉低至少 $18\text{ms}$，隨後拉高 $20 \sim 40\mu\text{s}$。
  • 感測器響應 (Response Signal)：DHT11 拉低 $80\mu\text{s}$，再拉高 $80\mu\text{s}$。
  • 位元脈寬解碼：每個 Bit 以 $50\mu\text{s}$ 低電平引導，後續高電平維持時間決定數值：
    • Bit "0"：高電平維持 $26 \sim 28\mu\text{s}$
    • Bit "1"：高電平維持 約 $70\mu\text{s}$
  • 校驗和公式 (Checksum Verification)： $$\text{Checksum} = (\text{Humi\_Int} + \text{Humi\_Dec} + \text{Temp\_Int} + \text{Temp\_Dec}) \pmod{256}$$

5. 自我發熱 (Self-Heating) 與熱平衡取樣延遲限制

⚠️
為什麼程式碼中嚴格要求 delayMS >= 1500？
電流通過感測元件與內部微處理器時會產生焦耳熱（$P = I^2 R$）。若主迴圈高頻連續取樣，積聚的熱量會使感測器內部微環境溫度上升，導致量測出的相對濕度產生嚴重的負偏差（大幅偏低且失真）。因此必須保留至少 1.5 ~ 2 秒間隔讓元件與環境充分進行熱交換。

1.3 HD44780 內建度數符號 `(char)223` 與尾端補空格防殘留技巧

在使用者實測驗證的整合程式中，展現了兩項極具實用價值的專業技巧：

  1. 內建字模度數符號 (char)223： Hitachi HD44780 點陣控制器內建的字庫 ROM（A00 標準版）在字碼 223 (十六進制 0xDF) 定義了日文半形句點／圓圈符號。透過 lcd.print((char)223); 即可直接印出度數圓圈 °，無須占用額外 CGRAM 空間！
  2. 尾端補空白防殘留字元 (Padding Technique)： 當溫度從兩位數（如 25.4°C）變為個位數（如 9.8°C）時，如果不做處理，原本位置最後方的舊字元會留在螢幕上。在數值後面補印空白（lcd.print("C "); 與 lcd.print("% ");），能確保完整覆寫舊字元，既乾淨俐落又無需呼叫劇烈閃爍的 lcd.clear()。

4.2 DHT11 溫濕度獨立測試程式碼 (Adafruit Unified Sensor 範例)

1015.txt 節錄 (DHT11 單元測試) 
// DHT Temperature & Humidity Sensor - Unified Sensor Library Example
#include <Adafruit_Sensor.h>
#include <DHT.h>
#include <DHT_U.h>

#define DHTPIN 8       // DHT 感測器接在數位 Pin 8
#define DHTTYPE DHT11  // 感測器型號 DHT11

DHT_Unified dht(DHTPIN, DHTTYPE);
uint32_t delayMS;

void setup() {
  Serial.begin(9600);
  dht.begin();
  
  sensor_t sensor;
  dht.temperature().getSensor(&sensor);
  dht.humidity().getSensor(&sensor);
  
  delayMS = sensor.min_delay / 1000; // 取得感測器規格最小延遲
}

void loop() {
  delay(delayMS);
  
  sensors_event_t event;
  dht.temperature().getEvent(&event);
  if (isnan(event.temperature)) {
    Serial.println(F("Error reading temperature!"));
  } else {
    Serial.print(F("Temperature: "));
    Serial.print(event.temperature);
    Serial.println(F("°C"));
  }

  dht.humidity().getEvent(&event);
  if (isnan(event.relative_humidity)) {
    Serial.println(F("Error reading humidity!"));
  } else {
    Serial.print(F("Humidity: "));
    Serial.print(event.relative_humidity);
    Serial.println(F("%"));
  }
}

1015-dht11.ino (完整整合驗證程式) 
#include <Wire.h> 
#include <LiquidCrystal_I2C.h>
#include <Adafruit_Sensor.h>
#include <DHT.h>
#include <DHT_U.h>

// --- 硬體腳位與設定 ---
#define DHTPIN 8          // DHT 感測器接在數位腳位 8
#define DHTTYPE DHT11     // 感測器型號 DHT11

// 設定 LCD：位址通常為 0x27，規格為 16 字元、2 行
LiquidCrystal_I2C lcd(0x27, 16, 2);
DHT_Unified dht(DHTPIN, DHTTYPE);

uint32_t delayMS;

void setup() {
  Serial.begin(9600);

  // 初始化 LCD 螢幕與背光
  lcd.init();
  lcd.backlight();
  lcd.clear();

  // 初始化 DHT 感測器
  dht.begin();

  // 取得 DHT 感測器所需的最小讀取間隔時間（DHT11 通常至少需 1~2 秒）
  sensor_t sensor;
  dht.temperature().getSensor(&sensor);
  delayMS = sensor.min_delay / 1000;
  if (delayMS < 1500) {
    delayMS = 1500; // DHT11 建議間隔至少 1.5 秒以上較為穩定
  }

  // 開機提示畫面
  lcd.setCursor(0, 0);
  lcd.print("Initializing...");
  delay(1000);
  lcd.clear();
}

void loop() {
  // 等待感測器間隔
  delay(delayMS);

  sensors_event_t event;

  // --- 讀取並顯示溫度（第 1 行）---
  lcd.setCursor(0, 0);
  lcd.print("Temp: ");
  dht.temperature().getEvent(&event);
  if (isnan(event.temperature)) {
    lcd.print("Error   ");
  } else {
    lcd.print(event.temperature, 1); // 顯示小數點後 1 位
    lcd.print((char)223);            // LCD 內建的度數符號 '°'
    lcd.print("C  ");                // 後方補空格避免位數變短時殘留舊字
  }

  // --- 讀取並顯示濕度（第 2 行）---
  lcd.setCursor(0, 1);
  lcd.print("Humd: ");
  dht.humidity().getEvent(&event);
  if (isnan(event.relative_humidity)) {
    lcd.print("Error   ");
  } else {
    lcd.print(event.relative_humidity, 1); // 顯示小數點後 1 位
    lcd.print("%   ");
  }
}

3.1 DHT11 vs DHT22 (AM2302) 規格深度比較

量測規格 DHT11 (經濟入門款) DHT22 / AM2302 (高精度進階款) 實務選型指標
溫度量測範圍 $0^\circ\text{C} \sim 50^\circ\text{C}$ $-40^\circ\text{C} \sim 80^\circ\text{C}$ 零下結冰或高溫工業環境必選 DHT22
濕度量測範圍 $20\% \sim 90\%\ \text{RH}$ $0\% \sim 100\%\ \text{RH}$ 超低濕或濃霧飽和環境 DHT11 會失真
溫度量測誤差 $\pm 2.0^\circ\text{C}$ $\pm 0.5^\circ\text{C}$ 高精度恆溫控制推薦 DHT22 或 SHT31
濕度量測誤差 $\pm 5\%\ \text{RH}$ $\pm 2\%\ \text{RH}$ DHT22 重複性與長期穩定性顯著較佳
數值小數解析度 整數精度 (小數常為 0) 0.1 級解析度 (16-bit 浮點精度) 需要捕捉細微趨勢變化選 DHT22
