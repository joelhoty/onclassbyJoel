# 探究、問題解決與小型研究指引

> 本資料夾適用於各類探究、問題解決與小型研究。上層 `D:\CLASS_NOTE\AGENTS.md` 的規範（Metadata、MD+HTML 雙格式、提示詞紀錄、索引更新）仍然適用；本檔只補充研究流程。

## 1. 先界定問題，再決定做法

動手搜尋前，先在文件開頭寫清楚：

- **問題陳述**：要解決或回答什麼？
- **背景與限制**：對象、時間、預算、技能、環境等。
- **成功標準**：怎樣算解決或回答完成？
- **研究類型**（可複選）：實務問題、技術問題、概念理解、資料分析、方案比較、決策支援。

類型不明或範圍過大時，先向使用者確認，不要自行假設。

## 2. 搜尋與資料蒐集

1. 拆解中英文關鍵字，從多個角度搜尋，視主題涵蓋：
   - 原理與成因：問題為何發生、背景知識
   - 現成方案：既有工具、制度、做法（低門檻）
   - 進階或客製方案：自動化、程式、實驗、調查（高門檻，**僅在有必要時**）
   - 反例與批評：限制、失敗案例、爭議
2. 優先採用一手與權威來源（官方文件、論文、統計機構），再用二手整理；重要論點盡量交叉驗證。
3. 區分「事實」、「來源的主張」與「自己的推論」，並標示不確定之處。
4. 使用過的來源須列於文末「參考資料列表」：來源名稱、標題、真實原始網址（排除搜尋引擎轉址）、取得日期（YYYY-MM-DD）。

## 3. 文件結構（依主題裁剪，不必全部具備）

**必備：**
- 問題剖析（含關鍵概念或成因）
- 結論或建議（先寫結論，再寫依據）
- 參考資料列表
- 提示詞紀錄（見第 6 節）

**視需要加入：**
| 內容 | 何時使用 |
|---|---|
| 方案選型或決策流程圖（Mermaid） | 有多條路徑或判斷條件時 |
| 比較表（方法、原理、適用場景、優勢、限制與風險） | 有兩個以上候選方案時 |
| 具體行動步驟或檢查清單 | 實務、管理、教學類問題 |
| 程式碼（含註解、流程圖、複製按鈕） | 確實需要運算或自動化時 |
| 資料表、圖表、統計結果 | 有量化資料時 |
| 假設、方法、限制 | 小型研究或實驗，須說明可信度時 |

單純概念性或資訊整理型主題，寫清楚的文字加少量圖表即可，不要為了完整而硬湊章節。

## 4. 依主題選擇工具（不預設產生程式）

先問：「這個問題用什麼最能解決？」只選必要的工具；能用文件、表格或現成服務解決，就不要自己寫程式。

| 主題類型 | 較合適的產出或工具 |
|---|---|
| 概念理解、文獻整理 | 結構化筆記、概念圖、對照表、時間軸 |
| 方案比較、決策 | 比較表、加權評分表、決策流程圖 |
| 教學、管理、流程問題 | 步驟清單、範本、表單、現成數位工具 |
| 量化資料分析 | 試算表或 Python/R 分析、統計圖表 |
| 調查、訪談 | 問卷或訪談題綱、編碼表、結果摘要 |
| 實驗、硬體、專案 | 實驗設計表、電路或流程圖、原型、測試紀錄 |
| 自動化、重複性工作 | 腳本或小工具（附流程圖與註解） |
| 地理、時間、空間資訊 | 地圖、時間軸、視覺化頁面 |

若確定要寫程式或啟動工具：
- 在程式碼前先以流程圖說明邏輯，程式碼加註解。
- 實際執行並確認結果或畫面正常，再於文件中宣稱完成；無法驗證時要如實說明。
- 說明為何選擇此工具、有哪些不用程式的替代方案。

## 5. 品質檢查（交付前）

- 是否回應了「成功標準」？
- 結論是否有來源或資料支撐？推論是否已標明？
- 建議是否符合使用者的限制（成本、技能、時間）？
- 連結是否有效、引用是否可追溯？
- 圖表與工具是否實際檢查過？

## 6. 提示詞紀錄

每次建立、更新文件、執行工具或回應追問，都要把 Prompt 原文依序以增補（Append）方式放在檔案最後，並標記時間（YYYY-MM-DD HH:mm:ss）。不得覆蓋既有紀錄；格式依上層 `AGENTS.md` 規定。
