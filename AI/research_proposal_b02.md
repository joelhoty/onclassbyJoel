# 從視覺注意到互動決策：注意力優先（Attention-first）閉環研究提案

## 提案摘要

本研究探討一套使用固定紅綠藍（Red-Green-Blue, RGB）攝影機的視覺互動系統。系統不先假設畫面中一定會出現某個指定手勢，而是先從連續影像中找出可能值得投入處理資源的人物或局部變化，再選擇並維持焦點。當系統累積一段時間的可觀察證據後，才形成視覺事件，進一步產生受限的語意解讀與文字互動決策。

第一階段以揮手與疑似邀請握手作為評估案例，用來檢驗系統能否從「尚未命名的變化」逐步形成「可稽核的事件與回應」。這兩個案例不是底層注意力機制唯一能辨識的內容，也不是預先寫死的觸發條件。

本研究也保留一項重要的閉環假設：高階判斷除了接收視覺事件，也能對未來的觀察提出有限回饋，例如繼續注意某位人物、某個身體部位，或某項仍然缺少的證據。這種類比只用來說明選擇、維持、解讀與回饋等工程功能，不代表系統具有人類的主觀注意力，也不代表其神經或計算機制與人類相同。

本提案的目標是建立可以實作、比較及反證的研究問題，而不是宣稱系統已具備開放世界中的人類式理解能力。

## 提案狀態與主張邊界

這是一份研究與實作規劃文件，不是已完成的系統或實驗結果。文中描述的系統行為都屬於待驗證設計；動作（Motion）、新奇性（Novelty）、朝向（Orientation）、預測誤差（Prediction Error）、任務相關性（Task Relevance）與不確定性（Uncertainty）都是候選注意力變數，並非已證實的最佳公式或人類認知定律。

凡是尚未完成實證或第一手文獻驗證的技術、資料、評估與理論連結，只能視為可行的工程假設，不得寫成已成立的研究結論。

目前可接受的主張範圍是：在固定視角、有限互動類型、文字輸出與明確運算預算下，研究一套先選擇焦點、再形成事件，並允許受控語意回饋影響未來觀察的閉環系統。研究不涵蓋無限制的場景理解、真實心理意圖讀取、永久身分辨識或實體機器人動作控制。

### 名詞與標示方式

為了兼顧閱讀與實作，本版採用以下標示原則：

- 專有名詞首次出現時，以「中文（英文全名, 英文縮寫）」呈現；後文以中文或縮寫為主。
- 程式資料結構、欄位名稱與固定比較條件保留英文程式碼形式，例如 `AttentionCue` 與 `P3`，並在首次出現時補上中文說明。
- 「事件」只描述可觀察到的變化；涉及意圖或社會意義的內容一律稱為「解讀」或「假設」。

## 一、提案來源與原始動機

### 1.1 原始種子筆記

本提案源自使用者的[原始想法筆記](./basic_idea.md)。筆記以兩個日常場景提出問題：在人群中，有人朝觀察者揮手；或有人伸出手，似乎想進行握手互動。原始構想不是只分類一張手部影像，而是參考人類從複雜視野中注意到人物動作、持續聚焦、理解一段行為，最後作出反應的過程。

筆記因此提出：是否能結合「你只看一次」（You Only Look Once, YOLO）物件偵測模型的連續視覺辨識、影像差異資訊、目標追蹤與大型語言模型（Large Language Model, LLM）的判斷，形成從視覺觀察到互動決策的流程。

原始筆記結尾列出「打招呼」與「揮拳」兩個例子；後續對話才由使用者把最小可行產品（Minimum Viable Product, MVP）收斂為「揮手」與「邀請握手」，並將輸出限定為文字。本提案保留這段發展順序，不把後來才形成的範圍改寫成原始筆記已作出的決定。

`basic_idea.md` 保留為不可覆寫的研究種子。本輪提案建立前所記錄的安全雜湊演算法 256 位元（Secure Hash Algorithm 256-bit, SHA-256）值如下：


### 1.2 將原始動機轉成研究問題

原始想法帶出三個彼此相關、但必須分開驗證的問題：

1. 系統如何從包含多人與多種動作的連續視覺輸入中，選出有限的處理焦點？
2. 系統如何把焦點對象的跨影格變化整理成可觀察、可回溯的事件，而不是依賴單一影格猜測？
3. 系統如何根據事件作出受限的互動決策，並在證據不足時選擇繼續觀察、提出澄清或不回應？

分開處理這三個問題，可以避免把「偵測到人體」、「持續注意某人」、「辨識到一段動作」與「推論對方意圖」混稱為同一種理解能力。當系統失敗時，也能進一步判斷問題出在焦點選擇、事件形成，還是語意判斷。

### 2.2 使用者提出的三項核心轉折

#### 轉折一：區分視覺事件與事件的綜合判斷

`USER CORE INSIGHT`：使用者提出，系統可以先分為「視覺事件」與「視覺事件的綜合判斷」。如此一來，可觀察行為便不會與行為意義的解讀混在同一項輸出中。例如，手臂伸展與手掌張開可以先記為視覺事件；「可能邀請握手」只能是帶有不確定性的後續解讀。

`CO-DEVELOPED REFINEMENT`：後續對話才進一步把這項分界轉成可保存的事件紀錄、可修正的語意假設與受限互動決策。這些資料結構與限制屬於共同設計，不倒推成使用者一開始便已指定的格式。

#### 轉折二：判斷中樞應能回饋注意力與追蹤

`USER CORE INSIGHT`：使用者進一步指出，如果把 LLM 類比為接收資訊並作出判斷的「大腦中樞」，架構便不應只有從視覺輸入到決策的單向路徑。高階解讀應能回饋視覺事件追蹤與注意力維持紀錄，讓系統依照仍缺少的證據調整後續觀察。

`CO-DEVELOPED REFINEMENT`：共同推演將這種回饋限制為結構化且有時效的未來觀察建議。回饋不能改寫已保存的視覺證據，也不能因語意預期而強迫低階觀測符合特定結論。具體資料規格、時效與驗證規則都屬於工程方案。

#### 轉折三：先注意與聚焦，之後才形成事件名稱

`USER CORE INSIGHT`：使用者指出，程式原型可以預先指定追蹤揮手或握手；然而，人或機器人面對連續畫面時，不應以「已經知道接下來會出現哪一個手勢」作為注意力成立的前提。研究重點應是先注意到值得聚焦的變化、持續觀察，再形成事件判讀。

`CO-DEVELOPED REFINEMENT`：系統仍不可能完全沒有選擇準則或歸納偏向。共同推演因此把原本的手勢類別預設，提升為較一般的候選線索，例如動作開始、時間上的新奇變化、朝向、預測誤差、任務相關性與決策不確定性。這些線索是可供比較的設計變數，不是已驗證的認知模型。

### 2.3 想法演化

| 階段 | 主要問題 | 當時形成的理解 | 尚未解決的張力 |
|---|---|---|---|
| 原始類比 | YOLO 與 LLM 能否類比從視覺聚焦到互動反應？ | 連續辨識、差異、聚焦與決策需要串接 | 各模組的責任與可驗證主張尚未分開 |
| 受限 MVP | 固定攝影機能否辨識揮手／邀請握手並輸出文字？ | 先排除馬達控制與完整意圖推論 | 系統容易退化成預設類別的手勢辨識器 |
| 兩個責任領域 | 視覺事件和事件綜合判斷是否應分開？ | 觀測與解讀可以獨立保存、比較 | 資料流仍可能只有單向傳遞 |
| 閉環回饋 | 高階判斷能否要求視覺模組繼續蒐集特定證據？ | 語意層可以影響未來的追蹤與聚焦 | 初始焦點仍可能依賴已知手勢 |
| 注意力優先 | 未知事件如何先被注意、維持焦點，再形成名稱？ | 先以一般線索分配資源，再形成事件與解讀 | 注意力準則與研究效益仍需實驗比較 |

這段沿革不否定揮手與邀請握手作為 MVP 的價值，而是重新界定兩者的角色：它們是用來測試一套較一般流程的已標記案例，不代表系統只要尋找這兩種手勢，就完成了注意力研究。

## 三、核心研究問題

### 3.1 主問題

在固定 RGB 攝影機、有限運算資源與文字輸出的受控場景中，一套視覺互動系統能否在尚未確定事件類別以前，先根據一般性變化與任務相關線索選擇、維持或切換焦點；接著從連續證據形成可觀察事件，再由規則或 LLM 進行受限的綜合判斷；最後以不改寫歷史證據的方式，回饋後續注意力？

### 3.2 研究責任的切分

核心問題保留使用者提出的兩階段責任邊界，但不把系統簡化成只能單向傳遞資料：

1. **視覺事件責任領域**：在事件名稱尚未確定時，處理可觀察變化、焦點選擇與維持、跨影格追蹤及事件形成，回答「畫面中發生了什麼可見變化」。
2. **視覺事件綜合判斷責任領域**：結合事件、場景與近期互動，形成可修正的解讀和受限決策，回答「這項變化可能代表什麼、現在可以做什麼，以及還需要觀察什麼」。

兩個責任領域之間同時存在向前交接與對未來觀察的回饋。這項切分是研究責任的整體界線，不表示每個領域只能使用一個模型，也不表示注意力等同於 LLM 的文字解讀。

### 3.3 受限研究命題

本研究要檢驗的不是「系統是否能像人一樣理解所有行為」，而是以下較窄的命題：

> 在固定視角的受控環境中，先使用不依賴最終手勢標籤的一般性線索選擇並持續觀察目標，再形成可稽核事件，可能比只依賴單一影格分類或手勢專屬觸發，更適合支援跨影格互動事件的發現、目標維持與受限文字決策。高階語意回饋能否帶來額外效益，必須在相同觀測證據與獨立比較條件下驗證。

命題中的「可能」代表待檢驗的方向，不是研究結論。「一般性」也不等於完全沒有預設，而是指選擇準則不要求系統先辨識 `wave`（揮手）或 `handshake`（握手），才能開始聚焦。

## 四、核心概念區辨

| 概念 | 本提案中的操作性含義 | 明確不代表 |
|---|---|---|
| 視覺感知／偵測 | 從影像取得人物、區域、姿態或局部特徵等可觀察量 | 已知道哪個人重要，或已理解事件意義 |
| 注意力線索 | 事件尚未命名以前，某個人物或區域可能值得投入更多處理資源的變化或任務訊號 | 已完成手勢分類；也不是讀取心理狀態 |
| 焦點選擇與維持 | 在有限資源下決定注意誰或哪裡、維持多久，以及何時切換 | 永久身分辨識或無條件鎖定單一目標 |
| 追蹤 | 利用跨影格連續性，暫時關聯同一段觀測 | 永久辨識某個人，或在語意上認定「必然是同一人」 |
| 視覺事件形成 | 將一段時間內的可觀察變化整理成可追溯描述 | 直接判定友善、邀請或威脅等內在意圖 |
| 語意解讀 | 根據事件與前後文提出可修正、保留替代解釋的假設 | 改寫過去畫面，或把可能性包裝成確定事實 |
| 互動決策 | 從允許的輸出集合中選擇文字回應、澄清、等待或不回應 | 自由生成任意動作、直接控制馬達或略過安全政策 |
| 注意力回饋 | 根據尚未解決的問題，有限度調整未來觀察的對象、部位或時間範圍 | 讓高階預期竄改歷史證據，或讓慢速模型阻塞所有視覺處理 |

這些區辨讓「看到」、「注意」、「持續追蹤」、「形成事件」、「解讀」與「決定回應」成為不同研究對象。系統可以已經偵測到人物，卻尚未分配高成本焦點；也可以已形成可觀察事件，但暫時不採用任何社會意義的解讀。

## 五、研究範圍

### 5.1 納入範圍

- **感測條件**：單一固定 RGB 攝影機。固定視角可減少攝影機自身移動所造成的變化干擾，但不能提供可靠的絕對深度。
- **輸出形式**：以文字互動為主，包括回應、澄清、等待更多證據或不回應。
- **決策層級**：先處理可觀察事件與基本互動決策；真實心理意圖只作為不確定且可修正的延伸解讀。
- **MVP 評估案例**：揮手與疑似邀請握手。前者代表需要跨影格累積的反覆動作；後者代表容易與伸手取物、遞物或索取物品混淆的姿勢序列。
- **研究焦點**：注意力入口、焦點持續、時序事件形成、觀測與解讀分離，以及高階判斷對未來觀察的受控回饋。
- **比較原則**：注意力選擇、事件辨識與語意決策必須分開檢視，不能因一次自然語言回覆看似合理，就宣稱整體系統有效。

### 5.2 排除範圍

- 開放世界中的任意行為理解，或與人類相同的通用視覺智慧。
- 直接從二維 RGB 影像確定他人的心理意圖、社會關係或情緒。
- 移動攝影機、主動轉動鏡頭、深度感測與多攝影機融合。
- 機器人手臂、致動器、接觸安全與任何實體動作控制。
- 人臉辨識、永久身分資料庫或跨場域個人追蹤。
- 將 LLM 放入逐影格的低階辨識流程，或讓它成為感知管線持續運作的必要條件。
- 把功能類比提升為主觀經驗、神經結構或計算機制相同的認知主張。

### 5.3 揮手與邀請握手的正確定位

這兩類事件在研究中有三項用途：提供可錄製與標記的案例、呈現兩種不同的時序模式，以及暴露目標關聯與語意歧義。它們不是在視覺處理開始以前告訴系統「現在只要找這兩種手勢」，也不是所有注意力線索的名稱。

例如，尚未命名的局部動作可以先引發焦點。累積足夠的時序證據後，系統才形成「軀幹上方出現週期性手部動作」等可觀察事件，接著提出「可能在打招呼」的解讀。

同樣地，手臂伸展與手掌張開只能形成邀請握手的候選解讀，不能排除取物、遞物或索取物件。若證據不足，合理的輸出可以是維持觀察、提出澄清或不回應，而不是強制選擇一項心理意圖。

## 六、人類注意力類比的限制

本研究以人類視覺作為問題形成的靈感：資源有限的系統需要選擇並維持焦點、整合時序資訊，也可能依照目標回頭尋找更多證據。這項類比只停留在可操作的功能層次：

- 從多個候選中選擇處理對象。
- 在干擾下維持或切換焦點。
- 從跨時間的證據形成事件描述。
- 依照未解問題調整未來觀察。
- 根據受限解讀選擇互動回應。

本提案不因此主張系統具有主觀感受、意識、共同注意、社會理解或人類式意圖；也不主張工程模組對應特定腦區、神經機制，或採用與人類相同的計算原理。「LLM 如同判斷中樞」只是啟發研究設計的功能比喻，不是生物學或認知科學上的等價命題。在後續證據不足以支持跨領域推論時，相關敘述都維持為設計假設或研究問題。

## 八、注意力優先（Attention-first）閉環架構

### 8.1 兩個整體責任領域

系統維持兩個可獨立稽核的整體責任領域。

**視覺事件責任領域**接收連續影格，產生不以最終手勢類別命名的注意力線索；接著在運算預算內選擇、維持或切換焦點，暫時關聯跨影格軌跡，最後形成只描述可見變化的事件。

**視覺事件綜合判斷責任領域**接收已發布事件，使用規則或 LLM 結合受限的前後文，提出可修訂的解讀、選擇允許的文字互動決策；必要時，再發出有限的未來證據蒐集指令。

兩個責任領域向前交接時，以資料規格（Data Contract）作為界線；反向路徑只傳遞有時效且可驗證的注意力指令 `AttentionDirective`。語意層不能直接更改追蹤狀態、焦點歷史或已發布事件，也不能把某項解讀當成低階觀測事實。

### 8.2 五個功能階段與主要資料流

固定 RGB 攝影機的連續影格依序進入五個功能階段：

1. **一般性線索生成**：由動作開始、時間上的新奇變化、朝向、預測誤差、任務相關性或觀測不確定性產生注意力線索 `AttentionCue`。線索回答「哪個可見區域可能值得投入更多資源」，不先判斷它是不是揮手或邀請握手。
2. **注意力管理與追蹤**：注意力管理器（Attention Manager）對候選線索排序，在有限運算預算下執行選擇（Select）、維持（Maintain）或切換（Switch）；選擇歷史寫入焦點紀錄 `FocusRecord`，並以追蹤狀態 `TrackState` 維持目標的暫時跨影格連續性。
3. **時序事件形成**：事件形成器只從焦點期間的影格、線索與追蹤狀態累積時序證據。達到明確的結束條件或時間範圍後，發布描述可見變化的視覺事件 `VisualEvent`。
4. **語意整合**：規則或 LLM 讀取 `VisualEvent` 與允許使用的近期前後文，建立可保留替代解釋、也能隨新證據修訂的解讀假設 `InterpretationHypothesis`。若缺少可區分假設的證據，語意層可以提出有界的 `AttentionDirective`，但不能因此阻塞視覺處理。
5. **互動決策**：決策器根據通過驗證的假設、可用證據與政策限制，產生互動決策 `InteractionDecision`。允許的輸出只有文字回應、澄清、等待或不回應。

主要資料流可以寫成：

> 連續影格 → 一般性注意力線索 `AttentionCue` → 注意力管理器選擇／維持／切換 → 時序事件形成 → 規則或 LLM 語意整合 → 互動決策

語意整合到注意力管理器另有一條受控回饋路徑。這條路徑用來影響未來觀察，不是反向覆寫主要資料流。

### 8.3 注意力優先成立的必要條件

注意力優先的必要條件是：系統在尚未產生 `wave` 或 `handshake` 等語意標籤以前，便能因一般性的可見變化而開始聚焦。

揮手或握手專用偵測器（Detector）可以在焦點建立後，作為事件形成或比較元件，但不能成為開始聚焦的必要閘門。即使專用偵測器沒有執行、沒有命中或暫時無法使用，注意力管理器仍應能根據一般性的 `AttentionCue` 選出值得觀察的人物或區域。

視覺事件採用可觀察的名稱，例如：

- `periodic_hand_motion_above_torso`：軀幹上方的週期性手部動作。
- `arm_extension_open_palm`：手臂伸展且手掌張開。
- `hand_moves_toward_nearby_object`：手朝附近物件移動。

`wants_handshake`（想要握手）、`is_friendly`（表現友善）或 `is_threatening`（具有威脅性）等涉及心理意圖或社會意義的名稱，不得作為 `VisualEvent.event_type`。這些內容只能出現在 `InterpretationHypothesis`，而且必須標示不確定性與替代解釋。

### 8.4 注意力管理的固定規則

注意力管理器使用可重現的排序規則，合併線索強度、時間新奇性、任務相關性、追蹤品質，以及仍在有效期限內的指令加權。接著，系統依每個時間範圍內的候選數、可同時維持的焦點數，以及高成本處理配額分配運算預算。

預算不足時，系統可以降低候選項目的更新頻率，或只保留低成本追蹤，但不能把尚未處理的候選記成「沒有事件」。每次選擇都要保留獲選目標、略過的候選、當時預算與排序依據。

為避免分數接近時頻繁切換焦點，切換規則必須同時考慮遲滯（Hysteresis）、切換成本（Switching Cost）與最短停留時間（Minimum Dwell Time）。只有在目前焦點已達最短停留時間，而且新候選的調整後分數持續高於保留門檻時，才允許切換。安全事件或追蹤完全失效等例外情況，必須另外記錄原因。

目標短暫被遮擋時，系統可以在有限的寬限時間內，利用暫時軌跡識別碼與預測位置維持焦點，同時降低追蹤品質。若超過寬限時間仍沒有可見證據，焦點必須結束，不能依賴語意猜測無限延長。目標重新出現時，若關聯證據不足，就建立新的追蹤軌跡，不宣稱它具有相同的永久身分。

每次焦點開始或結束時，都要記錄時間、焦點與追蹤識別碼、觸發線索或有效指令、排名與預算快照、選擇／維持／切換／結束原因，以及作出決策的元件版本。這些來源歷程（Provenance）可協助研究者判斷事件漏失究竟源於沒有偵測到線索、沒有取得預算、追蹤中斷，還是事件形成失敗。

## 九、雙時間尺度與回饋路徑

### 9.1 快速迴圈（Fast Loop）：不可被語意模型阻塞

快速迴圈逐影格或以短時間範圍執行線索生成、候選排序、焦點維持／切換、低成本追蹤與事件證據累積。它只讀取已通過結構規格（Schema）、時間與權限驗證的最新指令快照；不會同步呼叫 LLM，也不會等待 LLM 回覆後才處理下一個影格。沒有有效指令時，快速迴圈仍依一般性線索與本地確定性規則持續運作。

快速迴圈遇到依賴失敗時，採用可重現且不阻塞的降級處理（Fallback）：

- **逾時（Timeout）**：保留上一個仍有效的本地狀態與排序規則；如果沒有有效指令，就只依一般性線索排序，不等待重試結果。
- **結構規格無效（Schema Invalid）**：拒絕整筆輸入並記錄原因，不猜測或補填部分欄位；快速迴圈改用純線索路徑繼續。
- **模型無法使用（Model Unavailable）**：略過模型增強與新的語意回饋，改用規則式事件形成、既有有效指令或純線索降級路徑。模型恢復後，也不重新計算歷史證據。

相同的有效輸入、設定版本與狀態快照，必須得到相同的降級行為。降級處理可以減少語意內容，但不可停止影格擷取、焦點管理或事件紀錄。

### 9.2 慢速迴圈（Slow Loop）：可修訂解讀，但不可改寫觀測

慢速迴圈由已發布的 `VisualEvent`，或需要重新判斷的解讀所觸發。它在較長的時間尺度上執行規則／LLM 語意整合、替代假設比較、文字決策與證據請求。慢速迴圈可以產生新的 `InterpretationHypothesis` 修訂版，也可以提出 `AttentionDirective`；其處理延遲不構成快速迴圈的完成期限（Deadline）。

若慢速迴圈逾時、輸出不符合結構規格或模型無法使用，決策層採固定的降級順序：先使用已驗證的規則式解讀；如果證據仍然不足，就輸出「等待更多證據」或「不回應」。未完成或無效的模型輸出不會進入共享狀態，也不能轉成自由文字指令控制注意力管理器。

### 9.3 受控回饋與失效邊界

合法回饋以 `AttentionDirective` 表示。它只能調整未來候選的優先順序或觀測配置，例如在指定觀測期間內，提高某個暫時追蹤目標的手部區域觀測優先度。

每項指令必須包含目標（Target）、觀測項目（Watch）、原因（Reason）、觀測期間（Horizon）、存活時間（Time to Live, TTL）與優先度（Priority）等受控欄位。它通過結構規格、目標存在性、允許的觀測類型、優先度上限與到期時間驗證後，才可在下一個快速迴圈邊界生效。

指令不可指定應得到哪一種事件結論，不可要求修改既有 `VisualEvent`，也不可讓單一目標超出硬性運算預算。無效或已到期的指令必須被拒絕，並留下拒絕原因與來源歷程；快速迴圈則以沒有該指令的確定性路徑繼續。有效指令到期、目標消失或指定觀測期間結束後，會自動失效，不形成永久偏向。

回饋只改變未來的證據蒐集（Future Evidence Collection）。指令生效前已記錄的線索、焦點、追蹤與事件都保持原樣；生效後的新證據則附上指令識別碼，讓研究者能辨識該次觀測是否受到由上而下請求（Top-down Request）的影響。語意假設可以因新事件而修訂，但新版必須連結前一版，不得回填或竄改舊版。

## 十、資料契約與證據不可變規則

### 10.1 契約共同規則

七種契約各自使用不同識別碼與責任邊界，不能把所有內容混裝在一個可任意增加欄位的「事件物件」中。每筆紀錄至少應包含 `schema_version`、自身識別碼、來源元件及其版本、來源紀錄識別碼、事件發生時間與寫入時間。品質欄位只描述觀測或處理的可靠度，不能當成心理意圖的機率；不確定性若未經可靠校準，只能標示為相對等級或未校準分數。

`VisualEvent` 一旦發布，就採僅附加寫入（Append-only）原則。若低階證據或事件組裝有誤，必須新增帶有 `supersedes_event_id` 與更正理由的事件版本；舊紀錄仍須保留並可讀取，不能靜默覆寫。`InterpretationHypothesis` 可以修訂，但每次修訂都要新增版本並連結 `previous_hypothesis_id`。`AttentionDirective` 只能影響生效時間之後的證據。所有契約都禁止把語意推測回填為原始觀測。

### 10.2 注意力線索 `AttentionCue`

- **目的**：表示某個可見人物或區域目前可能值得分配額外處理資源，不承諾最終事件類別。
- **來源／輸入**：連續影格、低階偵測，以及動作、新奇性、朝向或預測誤差等一般性線索產生器；可關聯既有的暫時追蹤目標。
- **主要欄位**：`cue_id`、`observed_at`、`region_or_track_ref`、`cue_type`、`strength`、`spatial_extent`、`valid_until`。
- **品質／不確定性**：`measurement_quality`、`noise_flags`、`strength_calibration`，用來明示遮擋、模糊或分數尚未校準。
- **來源歷程**：影格／時間範圍識別碼、感測器識別碼、線索產生器名稱、模型／規則版本與參數版本。
- **允許／禁止操作**：允許排序、合併、到期，或保留為尚未獲得預算的候選；禁止直接命名為 `wave`／`handshake`、推論意圖，或因未被選中而刪除其存在紀錄。

### 10.3 焦點紀錄 `FocusRecord`

- **目的**：保存注意力管理器對焦點執行選擇（Select）、維持（Maintain）、切換（Switch）或結束（End）的決策歷史。
- **來源／輸入**：有效 `AttentionCue`、當下 `TrackState`、運算預算快照與已驗證的 `AttentionDirective`。
- **主要欄位**：`focus_record_id`、`focus_id`、`action`、`target_ref`、`started_at`／`ended_at`、`ranking_snapshot`、`budget_snapshot`、`reason_code`、`directive_id`（可空）。
- **品質／不確定性**：`selection_margin`、`target_visibility`、`decision_quality_flags`，用來區分排名差距太小、遮擋與預算降級等情況。
- **來源歷程**：輸入線索／追蹤／指令識別碼、注意力管理器版本，以及遲滯、切換成本與最短停留時間的設定版本。
- **允許／禁止操作**：允許新增維持、切換或結束紀錄；禁止事後改寫焦點開始原因、把目標鎖定（Target Lock）當成永久身分，或由慢速迴圈直接覆蓋歷史選擇。

### 10.4 追蹤狀態 `TrackState`

- **目的**：在有限時間內關聯同一可見目標的跨影格位置與姿態狀態，支援焦點維持和事件形成。
- **來源／輸入**：影格偵測、局部特徵、動作預測、焦點範圍及前一筆追蹤狀態。
- **主要欄位**：`track_state_id`、`track_id`、`observed_at`、`bbox_or_keypoints`、`velocity_or_motion_state`、`visibility_state`、`occlusion_age`、`association_status`。
- **品質／不確定性**：`detection_quality`、`association_quality`、`pose_quality` 與遮擋／模糊旗標；預測位置必須與實際觀測分開。
- **來源歷程**：來源影格與偵測識別碼、追蹤器／姿態元件版本、前一筆 `track_state_id`，以及資料關聯方法版本。
- **允許／禁止操作**：允許在短暫遮擋寬限期間（Brief Occlusion Grace Window）內標記為預測狀態，並在關聯失敗時結束舊軌跡、另建新軌跡；禁止聲稱永久人物身分、在沒有觀測時無限延伸，或依語意假設更改過去座標。

### 10.5 視覺事件 `VisualEvent`

- **目的**：發布一段時間內發生的可觀察視覺變化，作為觀測與語意解讀之間的穩定證據邊界。
- **來源／輸入**：一個或多個 `FocusRecord`、`TrackState`、`AttentionCue` 及其時間範圍；事件形成器不得使用待證明的心理意圖作為輸入標籤。
- **主要欄位**：`visual_event_id`、`event_type`、`start_at`、`end_at`、`actor_track_refs`、`object_or_region_refs`、`observable_attributes`、`temporal_pattern`、`evidence_refs`、`supersedes_event_id`（可空）。
- **品質／不確定性**：`observation_quality`、`temporal_completeness`、`association_quality`、`ambiguity_flags`；觀測品質低不代表某種意圖的機率較高。
- **來源歷程**：所有來源線索／焦點／追蹤識別碼、事件形成器與結構規格版本、時間範圍界線，以及當時生效的指令識別碼（若有）。
- **允許／禁止操作**：允許發布可觀察名稱，並以僅附加的新版本更正技術錯誤；發布後禁止靜默改寫，也禁止使用 `wants_handshake`、`friendly` 等心理或社會結論作為事件名稱。

### 10.6 解讀假設 `InterpretationHypothesis`

- **目的**：對一個或多個事件提出暫時的語意解讀，同時保留競爭假設與未知狀態。
- **來源／輸入**：已發布的 `VisualEvent`、允許使用的近期互動前後文、規則庫或 LLM 結構化輸出。
- **主要欄位**：`hypothesis_id`、`revision`、`claim_label`、`supporting_event_ids`、`alternative_labels`、`context_refs`、`status`、`previous_hypothesis_id`（可空）。
- **品質／不確定性**：`confidence_or_rank`、`calibration_status`、`missing_evidence`、`contradictions`；未校準的信心分數不得表述成客觀機率。
- **來源歷程**：規則／模型名稱與版本、提示詞／政策版本、輸入事件與前後文識別碼，以及產生時間。
- **允許／禁止操作**：允許新增修訂版、降低信心、撤回或保留多個假設；禁止修改來源事件、把假設轉寫成觀測事實，或只因 LLM 措辭流暢就移除替代解釋。

### 10.7 注意力指令 `AttentionDirective`

- **目的**：將慢速迴圈仍缺少的區辨證據，轉成對未來觀察提出的有限且可拒絕請求。
- **來源／輸入**：`InterpretationHypothesis.missing_evidence`、規則式歧義處理，或通過結構規格驗證的 LLM 輸出。
- **主要欄位**：`directive_id`、`issued_at`、`target`（追蹤／區域參照）、`watch`（允許的可觀察量）、`reason`、`horizon`、`ttl`／`expires_at`、`priority`、`requested_budget_class`。
- **品質／不確定性**：`request_confidence`、`target_resolution_quality`、`validation_status`；品質不足時直接拒絕，不由快速迴圈猜測目標。
- **來源歷程**：來源假設／事件識別碼、產生規則或模型版本、驗證器與政策版本、接受或拒絕時間，以及原因代碼。
- **允許／禁止操作**：允許在硬性預算與優先度上限內，提高未來目標／觀測項目的處理優先度；禁止改寫歷史證據、指定應得出的語意結論、無期限鎖定目標，或要求自由格式的低階動作。指令無效、已到期或無法解析目標時必須拒絕，快速迴圈不得因此阻塞。

### 10.8 互動決策 `InteractionDecision`

- **目的**：在允許集合中，記錄系統此刻是否以及如何進行文字互動。
- **來源／輸入**：有效 `InterpretationHypothesis`、直接支持它的 `VisualEvent`、決策政策、安全限制與近期互動狀態。
- **主要欄位**：`decision_id`、`decided_at`、`decision_type`（`respond`／`clarify`／`wait`／`no_response`）、`text_payload`（可空）、`hypothesis_refs`、`event_refs`、`policy_reason`。
- **品質／不確定性**：`decision_confidence_or_rank`、`evidence_sufficiency`、`risk_flags`；證據不足時要保留不足狀態，不能強制生成回覆。
- **來源歷程**：決策器、規則／模型與政策版本、所有輸入假設／事件識別碼，以及降級原因（若有）。
- **允許／禁止操作**：允許輸出受限文字、澄清、等待或不回應；禁止直接控制致動器、宣稱未知心理意圖為事實，或用決策結果反向更改觀測契約。

### 10.9 代表性歧義追蹤

假設快速迴圈先因手臂局部動作產生一般性的 `AttentionCue`，注意力管理器在不知道事件名稱的情況下建立焦點。跨影格證據之後形成並發布 `VisualEvent(event_type = arm_extension_open_palm)`。這個名稱只表示可見的手臂伸展與手掌張開，不把行為直接寫成邀請握手。

慢速迴圈根據同一事件建立三個可區分的 `InterpretationHypothesis`：邀請握手（Handshake Invitation）、伸手取物（Object Reach）與索取物件（Request for Object）。因為單一事件不足以排除其中任何一項，系統不會立即把某個假設當成事實，而是產生有 TTL 限制的證據請求。

此時，`AttentionDirective.target` 指向同一個暫時追蹤目標；`watch` 只允許觀察「手與附近物件的距離變化、手掌方向、另一人的接近或伸手回應」；`reason` 記錄需要區分的三個假設；`horizon` 限定後續短時間範圍；`priority` 則受硬性上限約束。

若有效期間內觀察到手朝附近物件移動，新 `VisualEvent` 可以支持伸手取物；若另一人也伸手接近，則可以提高邀請握手的相對排序。若沒有取得足以區辨的證據，指令到期後，快速迴圈仍照常處理其他線索，互動決策則採等待、澄清或不回應。無論結果為何，原始 `arm_extension_open_palm` 事件保持不變；新增事件與解讀假設修訂版透過引用鏈呈現判斷如何演變。

## 十一、不依賴 LLM 的確定性基線與 LLM 擴充

### 11.1 `S0 — deterministic`：不依賴 LLM 的完整可執行路徑

本研究要求，即使完全不使用 LLM，系統仍可從結構化觀測走到可重現的文字決策。最小閉環依序包含：結構化觀測／事件（Structured Observations／Events）→ 品質閘門（Quality Gate）→ 狀態機（State Machine）→ 衝突／歧義路由器（Conflict／Ambiguity Router）→ 白名單式互動政策（Allowlisted Interaction Policy）→ 確定性文字範本（Deterministic Text Template）。

這條路徑先驗證注意力、追蹤、事件形成與基本決策是否能獨立成立，避免把所有成功都歸因於語言模型表面上流暢的文字。

品質閘門負責拒絕品質不足或關聯失敗的輸入。例如，當 `TrackState.association_quality` 低於門檻、關鍵手部觀測缺失、遮擋過久，或 `VisualEvent` 只有單一影格支持時，事件可以降級為未知（Unknown）、歧義（Ambiguous），或暫不發布。狀態機只操作觀測狀態，例如 `no_focus`、`focus_active`、`event_candidate`、`event_confirmed`、`await_more_evidence`，不把心理意圖寫進狀態名稱。

衝突／歧義路由器在多種可見解釋同時成立時，會保留競爭候選，不強迫選出單一結論。以 `arm_extension_open_palm` 為例，路由器必須能同時保留 `handshake_candidate`、`object_reach`、`object_pass` 與 `request_for_object`，再交由白名單式互動政策決定輸出等待、澄清或不回應。白名單只允許預先定義的文字輸出類型，例如打招呼、澄清、等待更多證據或不回應，不允許自由產生未經審核的動作類型。

確定性文字範本只根據結構化決策欄位產生文字，例如：

- `respond:greeting` →「你好，我注意到你可能在打招呼。」
- `clarify:handshake_candidate` →「我看到你伸出手，但還不確定是要握手還是拿取物品。」
- `wait:more_evidence` →「目前先持續觀察，不立即回應。」

因此，即使完全移除 LLM，系統仍應能對揮手、具有歧義的握手候選，以及高難度反例（Hard Negative）提供可檢查、可重播的文字決策或保留判斷（Abstention）。

### 11.2 `S1 — LLM response`：只擴充文字表述

`S1 — LLM response` 讀取與 `S0` 相同的 `VisualEvent`、`InterpretationHypothesis` 候選與政策邊界，只能在既有決策類型內產生較自然的文字回應。它不能新增事件，不能改變 `decision_type` 白名單，也不能把證據稀少的決策包裝成高信心陳述。若模型失敗，系統回到確定性文字範本。

### 11.3 `S2 — LLM clarification`：只擴充歧義處理

`S2 — LLM clarification` 在 `S1` 基礎上，可以根據競爭假設產生受限的澄清問題或說明文字，例如區分「你是在跟我打招呼嗎？」與「你是要把物品遞給旁邊的人嗎？」。但輸出仍必須映射到 `clarification_goal`、`target_hypotheses`、`text_payload` 等結構化欄位，不能超出白名單式政策。若結構化輸出驗證失敗，系統沿用 `S0` 的固定澄清規則。

### 11.4 `S3 — LLM attention feedback`：有界的由上而下語意回饋

`S3 — LLM attention feedback` 是功能最完整的版本，但 LLM 的角色仍嚴格限制於事件層級語意整合（Event-level Semantic Integration）、澄清（Clarification）、解釋（Explanation）、回應提案（Response Proposal），以及結構化的 `AttentionDirective`。它可以根據已發布事件指出下一步應觀察哪個目標、哪些可觀察量及持續多久，例如要求系統在短時間內提高某個追蹤目標的手部與鄰近人物距離之觀測優先度。

這個版本必須受到結構規格、白名單、來源歷程與降級處理保護：

- **結構規格**：輸出必須符合固定欄位與型別，不能夾帶自由指令。
- **白名單**：觀測類型、優先度上限、要求的預算類別與決策類型，都必須在預先允許的集合中。
- **來源歷程**：保留模型名稱、模型版本、提示詞版本、輸入事件／假設識別碼與驗證器結果。
- **降級處理**：任何逾時、結構規格無效、目標無法解析或政策拒絕，都回到 `S0`／`S2` 路徑，不阻塞快速迴圈。

`S3` 明確禁止四類行為：改寫感知證據（Perception Evidence）、執行任意程式碼（Arbitrary Code）、繞過白名單（Bypass Allowlist），以及直接控制馬達（Direct Motor Control）。它也不能直接宣稱某個人「一定想握手」；只能提出需要補充哪些觀測的結構化建議，或保持不確定性的受限解讀。

## 十二、代表性案例與端到端追蹤

### 12.1 固定 RGB 攝影機與文字輸出的案例設定

代表性案例全部限制在固定 RGB 攝影機、單機文字輸出與短時序互動。如此一來，注意力、事件與語意決策的比較都建立在相同感測條件上，不會混入深度感測、攝影機主動轉動或機器人致動器的影響。

第一輪案例固定為揮手、具有歧義的握手候選，以及高難度反例。每個案例都要同時追蹤不使用 LLM 的版本（No-LLM Variant）與閉環版本（Closed-loop Variant）。

### 12.2 揮手：由未命名變化形成打招呼決策

揮手案例中，不使用 LLM 的版本依下列步驟運作：

1. 某個人物上半身附近出現週期性手部動作，產生一般性的 `AttentionCue`。
2. 注意力管理器根據線索強度、時間持續性與可見度建立 `FocusRecord`。
3. `TrackState` 穩定維持同一個暫時目標；事件形成器累積多次方向反轉與手部高於軀幹的時序特徵。
4. 發布 `VisualEvent(event_type = periodic_hand_motion_above_torso)`。
5. `S0 — deterministic` 的狀態機將事件映射為 `greeting_candidate`。若觀測通過品質門檻，就輸出白名單內的打招呼文字；若品質不足，則改為等待或不回應。

閉環版本在第 4 步之後，允許 `S3 — LLM attention feedback` 讀取事件與短期前後文。若它判斷還需要確認揮手者是否朝向系統，就可以提出有 TTL 限制的 `AttentionDirective`，要求短時間提高臉部朝向與手腕方向變化的觀測優先度。只有當新觀測支持打招呼假設時，系統才提高回應順位；若不支持，就維持較保守的決策。無論結果如何，原始 `VisualEvent` 都不會被改寫。

### 12.3 具有歧義的握手候選：保留不確定性，不過早定論

具有歧義的握手候選中，不使用 LLM 的版本必須呈現下列過程：

1. 一般性的 `AttentionCue` 由手臂前伸或身體朝向變化觸發，不以握手類別已先命中為前提。
2. `VisualEvent` 只命名為 `arm_extension_open_palm`、`arm_extension_toward_person`，或其他可觀察的候選事件。
3. 衝突路由器同時保留 `handshake_candidate`、`object_reach`、`object_pass`、`request_for_object`。
4. 若缺少足以區辨的證據，`InteractionDecision` 輸出澄清、等待或不回應，不得把自然語言說得合理就當成握手判斷成功。

閉環版本允許 `S3` 發出 `AttentionDirective`，例如要求系統繼續觀察目標的手掌朝向、手與鄰近物件的距離變化、對方是否同步伸手，或互動對象是否接近。若取得指令要求的新觀測後仍無法區分，系統就必須維持歧義狀態，不能因模型文字流暢就把結果升格為握手成功。

### 12.4 高難度反例：證明並非所有顯著動作都需要回應

高難度反例至少包括：調整眼鏡（Adjusting Glasses）、抓癢（Scratching）、觸摸頭部（Head Touch）、指向（Pointing）、伸手取物（Object Reach）、遞物（Object Pass）、索取物件（Request for Object）、對另一人揮手（Waving to Another Person）、背景動作（Background Motion）、遮擋（Occlusion）與多人交錯（Multi-person Crossing）。

不使用 LLM 的版本必須能把這些情況記錄為沒有事件、其他事件，或不屬於目前互動政策的候選，不能把所有手部顯著變化都誤判為揮手或邀請握手。

閉環版本在高難度反例上的重點，不是增加回應數量，而是證明由上而下回饋不會增加焦點錯置或誤觸發（False Activation）。例如，背景人物向另一個人揮手時，語意層可以要求更多目標關聯證據；但若無法確認互動對象是系統本身，決策仍應維持不回應。

## 十三、研究目標、問題與假設

### 13.1 研究目標

本提案的研究目標是建立可被資料推翻的比較架構，分別檢驗：

1. 注意力目標選擇與焦點持續（Attention Selection／Persistence），是否優於較弱的比較基線。
2. 時序事件形成（Temporal Event Formation），是否優於單一影格或手勢專屬觸發。
3. 語意決策（Semantic Decision）能否在不過度推論意圖的前提下，提升文字互動品質。
4. LLM 回饋是否真的改善未來觀察，而不只是增加成本或造成焦點錯置。

### 13.2 研究問題

- `RQ1`：`P3 — attention-first` 是否比 `P0 — single-frame`、`P1 — full-time temporal`、`P2 — gesture-specific trigger` 更能提升注意力目標選擇／持續，以及聚焦所需時間（Time to Focus）？
- `RQ2`：在固定 RGB 攝影機條件下，注意力優先方法是否能提升揮手與可觀察握手候選的事件形成 F1 分數（F1 Score），同時降低誤觸發？
- `RQ3`：對同一份凍結事件串流（Frozen Event Stream），`S0 — deterministic`、`S1 — LLM response`、`S2 — LLM clarification` 在語意決策、保留判斷與澄清上有何差異？
- `RQ4`：在配對情境種子（Matched Scenario Seed）及相同的指令生效前共享前段（Shared Pre-directive Prefix）下，`S3 — LLM attention feedback` 的線上或重播式閉環配對比較，能否在可接受的延遲、模型呼叫率與運算成本內，改善下游注意力、事件、決策或歧義解決指標？
- `RQ5`：若自然語言回應看似合理，但注意力選擇、事件形成或證據充分性失敗，系統是否仍應判定為整體失敗？

### 13.3 可反證假設

- `H1`：相較於 `P0 — single-frame`，任何具有時間記憶的條件在揮手事件 F1 分數上都會較高；如果沒有較高，本提案所主張的短時序資訊必要性就會被削弱。
- `H2`：`P3 — attention-first` 會比 `P2 — gesture-specific trigger` 更快在未知事件起始時建立正確焦點，並降低多人交錯時的目標關聯錯誤；如果沒有優勢，注意力優先方法的研究價值就不足。
- `H3`：若 `P3` 的優勢只出現在語言輸出，沒有出現在目標選擇／持續或事件指標，就不能宣稱注意力已有改善。
- `H4`：`S2 — LLM clarification` 在具有歧義的握手候選中，會比 `S0 — deterministic` 提高正確保留判斷／澄清的比例，而且不會顯著增加錯誤的確定陳述；若反而增加過度自信判斷，就應回退到較弱版本。
- `H5`：只有當 `S3 — LLM attention feedback` 在配對情境種子與共享前段的比較中，改善指令生效後可分歧事件串流裡至少一項下游注意力、事件或語意指標，且沒有造成不可接受的延遲、焦點錯置或成本時，才算具有研究價值；否則應停止使用 `S3`，或降級為 `S2`／`S0`。

以上假設都不把流暢的自然語言當成整體成功的替代指標。整體成功必須同時檢視注意力、事件、語意決策與回饋成本。

## 十四、研究方法與比較設計

### 14.1 研究設定

研究場景使用固定 RGB 攝影機、室內可控背景、已充分知情同意的成年參與者，以及文字輸出介面。第一階段先錄製單人與雙人的近距離場景，再延伸到多人交錯、局部遮擋與背景干擾。所有條件都不使用深度攝影機，不進行人臉辨識或建立永久識別碼，也不要求任何實體動作輸出。

### 14.2 規劃中的參與者與錄影

後續原型階段規劃先邀請成年同意者，錄製小型先導資料集（Pilot Dataset），內容包括：

- 單人朝攝影機方向揮手打招呼。
- 單人朝攝影機前方伸手，但無法直接判定是否邀請握手。
- 兩人互動，但揮手或伸手行為並非朝向系統。
- 多種高難度反例與背景動作。

這些參與者與錄影都只是規劃，尚未完成招募或收案。若研究日後進入人類參與者錄影階段，必須另外確認知情同意（Informed Consent）、場地告知與資料保存政策。

### 14.3 情境流程（Scenario Protocol）

每段錄影都應有明確的開始條件、互動動作、可能干擾與結束條件。揮手流程至少涵蓋不同速度、手部高度、身體朝向，以及是否真的朝系統揮手。握手候選流程至少涵蓋朝人伸手、朝物體伸手、遞物、索取物件與不完整伸手。高難度反例流程則要刻意放入調整眼鏡、抓癢、觸摸頭部、指向、背景動作與多人交錯。

### 14.4 資料切分與開發流程

若錄影數量足夠，資料分為訓練集（Training Set）、開發集（Development Set）與測試集（Test Set）；若樣本仍小，至少保留先導切分，或採開發集與保留集（Held-out Set）。所有門檻值、差距值、遲滯、最短停留時間、品質閘門與澄清政策，都只能在開發集上決定，之後凍結設定再進入測試。測試關卡的目的是讓注意力優先或 LLM 回饋的主張可被推翻，不是讓研究者繼續依測試結果調整參數。

主要保留／測試資料應優先採參與者互斥切分（Participant-disjoint Split），也就是每位參與者只出現在一個資料分區。若先導資料太少，至少要做到錄製階段互斥切分（Session-disjoint Split），避免同一場錄影的片段同時出現在開發與測試集合。

同一段錄影、同一事件的不同裁切版本或近似重複片段（Near-duplicate Clips），都不得跨越資料分區。若資料條件使部分重疊無法避免，該比較只能標記為探索性分析（Exploratory Analysis），不得用於主要研究主張。這些切分與識別碼仍只在單次錄製階段內有效，不建立可跨錄製階段回溯的永久身分。

### 14.5 標註單位（Annotation Units）

標註至少分為六個層次：

- **影格（Frame）**：人物／手部／物體可見性、關鍵點品質與遮擋旗標。
- **追蹤軌跡（Track）**：暫時目標關聯、識別碼切換與關聯信心。
- **焦點區間（Focus Interval）**：焦點開始／結束、維持／切換原因、聚焦所需時間與停留時間。
- **視覺事件（Visual Event）**：事件起訖、可觀察事件類型與時序模式。
- **解讀（Interpretation）**：可能的社會／互動意義、替代標籤與保留判斷的必要性。
- **決策（Decision）**：回應、澄清、等待或不回應，以及是否符合白名單式互動政策。

### 14.6 比較條件與消融設計

感知／注意力軸使用下列固定名稱：

- `P0 — single-frame`：單一影格。
- `P1 — full-time temporal`：全程時序處理。
- `P2 — gesture-specific trigger`：手勢專屬觸發。
- `P3 — attention-first`：注意力優先。

語意控制軸使用下列固定名稱：

- `S0 — deterministic`：確定性規則。
- `S1 — LLM response`：LLM 文字回應。
- `S2 — LLM clarification`：LLM 歧義澄清。
- `S3 — LLM attention feedback`：LLM 注意力回饋。

`S0`、`S1`、`S2` 採同一凍結事件串流的離線語意比較（Offline Semantic Comparison）。三者讀取完全相同且已凍結的 `VisualEvent` 與前後文，只比較確定性政策、LLM 回應及 LLM 澄清對決策、保留判斷與澄清的影響。

`S3` 不能放進上述「相同事件串流」的比較契約，因為它會主動改變後續觀測。`S3` 必須使用配對情境種子與同一段指令生效前共享前段，另外進行線上或重播式閉環配對比較（Online or Replay-closed-loop Paired Comparison）。指令生效後，各條件的事件串流可以分歧，因此應以後續注意力、事件、決策、延遲與運算成本評估 `S3`，不能假裝它與 `S0`–`S2` 共用完整的凍結事件串流。

主要比較包括：以 `P0` 對 `P1` 檢驗時間資訊是否必要；以 `P1` 對 `P2` 檢驗手勢專屬觸發的工程效益與限制；以 `P2` 對 `P3` 檢驗注意力優先是否真的優於先驗手勢觸發。`P2` 不得重新命名為注意力優先的證明。語意軸則先用同一凍結事件串流比較 `S0`、`S1`、`S2`，再用共享前段的配對比較，評估 `S3` 是否真的帶來閉環增益。

必要的消融實驗（Ablation Study）包括：移除一般性線索中的部分候選變數、移除遲滯、關閉指令 TTL、停用回饋，以及把使用相同事件串流的語意控制器換成確定性政策。這些實驗可協助判斷效益究竟來自時間記憶、焦點管理、語意澄清，還是單純來自較大的模型。

## 十五、資料蒐集、標註與高難度反例

### 15.1 資料蒐集原則

資料蒐集以最小可行研究為原則，先求可標註、可重播、可稽核，不追求一開始就擴大規模。每段錄影都要保留時間戳、場景設定、照明條件、參與者相對位置，以及是否包含其他人物。為避免把同一人長期追蹤成永久身分，資料紀錄只使用錄製階段內識別碼（Session-local ID）。

### 15.2 必含的高難度反例與邊界情境

資料集至少應包含下列高難度反例或混淆情境：

- 調整眼鏡（Adjusting Glasses）。
- 抓癢（Scratching）。
- 觸摸頭部（Head Touch）。
- 指向（Pointing）。
- 伸手取物（Object Reach）。
- 遞物（Object Pass）。
- 索取物件（Request for Object）。
- 對另一人揮手（Waving to Another Person）。
- 背景動作（Background Motion）。
- 遮擋（Occlusion）。
- 多人交錯（Multi-person Crossing）。

加入這些情境，是為了檢驗系統會不會只要看到顯著的手部變化，就輸出打招呼或握手相關決策。

### 15.3 標註內容

標註結構至少涵蓋：

- **影格**：可見人物、手部、物體、朝向、遮擋與品質。
- **追蹤軌跡**：目標關聯與識別碼切換。
- **焦點區間**：開始／結束時間、目標、原因代碼、停留與切換。
- **`VisualEvent`**：事件類型、起訖時間、可觀察屬性與歧義旗標。
- **解讀**：候選意義、替代假設與缺少的證據。
- **決策**：決策類型、是否應保留判斷，以及是否需要澄清。

如果某段錄影只足以支持可觀察事件，卻不足以支持社會意義解讀，標註就必須停在事件層，不能把未證明的意圖硬寫成真實標籤（Ground Truth）。

### 15.4 標註程序與一致性

至少採兩位標註者獨立標註，再進行分歧裁決（Adjudication）。兩位標註者分別標記影格、追蹤軌跡、焦點區間、事件、解讀與決策；意見不同時，裁決紀錄要保存最終決議與理由。

標註者間一致性（Inter-annotator Agreement, IAA）可分層計算，例如事件邊界一致性、事件標籤一致性、決策一致性，以及保留判斷必要性的一致性。若解讀層的一致性太低，就應縮小主張範圍，避免把模糊意義當成可穩定監督的標籤。

## 十六、評估指標、分析與可重現性

### 16.1 評估指標

指標必須分層報告，不能把所有錯誤混成單一準確率：

- **注意力目標選擇準確率（Attention Target Selection Accuracy）**：分母是需要選出主要目標的聚焦機會。
- **注意力持續品質（Attention Persistence Quality）**：分母是已建立焦點的目標持續區間，用來觀察系統是否過早切換或失去目標。
- **聚焦所需時間（Time to Focus）**：分母是具有明確事件起始的案例，量測從可見起始點到建立焦點的延遲。
- **停留時間（Dwell Time）**：分母是已建立焦點的區間，量測持續時間是否足以支援事件形成。
- **切換率（Switch Rate）**：分母是可以進行切換決策的時間點，用來觀察焦點是否過度抖動。
- **事件 F1 分數（Event F1 Score）**：由系統發布事件對標註事件的精確率（Precision）與召回率（Recall）共同計算。
- **誤觸發（False Activations）**：分母可以採每分鐘影片或每個非事件區間，但報告時必須明確說明採用哪一種。
- **延遲（Latency）**：分別報告快速迴圈延遲、事件發布延遲與語意決策延遲。
- **目標關聯準確率（Target Association Accuracy）**：分母是需要把觀測正確關聯到同一目標的影格或區間。
- **識別碼切換（ID Switches）**：分母可採有效追蹤軌跡或每分鐘交錯事件，但必須固定報告方式。
- **語意決策準確率／保留判斷準確率／澄清適切性**：分母是需要作出決策的案例。
- **模型呼叫率（Model Invocation Rate）**：分母可採每分鐘、每事件或每次決策；報告時必須固定一種並清楚註明。
- **運算成本（Compute Cost）**：包含圖形處理器（Graphics Processing Unit, GPU）／中央處理器（Central Processing Unit, CPU）時間、峰值記憶體與每個事件的平均成本。

### 16.2 失敗歸因（Failure Attribution）

每次失敗都要歸因到最接近的責任層：線索漏失、未分配焦點、追蹤碎裂、事件形成失敗、語意過度主張、澄清失敗、回饋造成焦點錯置，或觸發政策降級。這樣才能避免「文字回答看起來還可以」掩蓋注意力或事件層的問題。

### 16.3 分析方法

分析採配對條件（Matched Conditions）、配對比較（Paired Comparison）與必要的分層切片（Stratified Slices），例如單人／多人、遮擋／無遮擋、背景干擾／乾淨背景，以及揮手／握手候選／高難度反例。

統計摘要至少包含自助法信賴區間（Bootstrap Confidence Interval, Bootstrap CI）、效果量（Effect Size）與錯誤分類架構（Error Taxonomy），不只報告平均值。若某一條件的資料量太少，應標記為探索性分析，不能宣稱結論穩固。

### 16.4 可重現性紀錄

為使後續原型可以重播，至少記錄：

- 設定、門檻、差距值、遲滯、最短停留時間與品質閘門版本。
- 模型名稱、模型版本、提示詞版本、結構規格版本與政策版本。
- 隨機種子、資料切分、硬體規格與執行紀錄。
- 各階段延遲、模型呼叫、遭拒絕的指令與降級處理紀錄。

若使用第三方模型或服務，還要記錄當時可辨識的供應商版本與限制。所有紀錄只涵蓋研究系統的行為與設定，不包含可用來還原個人身分的資料。

### 16.5 隱私安全的釋出邊界（Privacy-safe Release Boundaries）

未來若分享資料或結果，只應釋出匿名化統計、標註結構規格、設定檔、彙整指標與可公開的程式邏輯；原始影像與可辨識人臉片段不得預設公開。若需要讓外部研究者重現，應優先釋出模擬樣本、遮罩示例或無法反推身分的衍生特徵，不直接提供完整且可識別的錄影。

## 十七、可行性、風險、倫理與授權

### 17.1 技術可行性與限制

固定的二維 RGB 攝影機（Two-dimensional RGB Camera）可簡化場景並降低設備成本，但無法可靠提供深度、接觸意圖與完整社會脈絡。揮手的可觀察性相對較高；邀請握手則可能始終只能停留在候選或歧義層。任何把二維姿態直接解讀成真實意圖的結論，都超出本提案能支持的範圍。

### 17.2 風險來源

主要風險包括人口特徵、外觀、照明與遮擋造成的偏差，姿態估計對不同身形或服飾的穩定度差異，多人交錯導致資料關聯失敗，以及背景動作造成注意力誤觸發。

如果失敗集中在特定外觀、身高、膚色或照明條件，研究必須把它明確記錄為限制，不能讓平均指標掩蓋群體間差異。

### 17.3 倫理與隱私

原型錄影只能邀請已充分知情同意的成年參與者，並清楚說明資料保存期限（Retention）、存取權限（Access）、刪除方式（Deletion）與使用範圍。系統不得進行人臉辨識、建立永久識別碼，或跨錄製階段追蹤個人。

如果場景可能拍到旁觀者，就必須建立旁觀者保護措施（Bystander Control），例如事前明確告知、避開收錄、套用遮罩或提供刪除流程。資料存取應採最小權限原則，並限於已說明的研究目的與可追蹤的授權範圍。

### 17.4 授權與第三方依賴

未來實作若使用 Ultralytics、MediaPipe、第三方模型、資料集或標註工具，必須先檢查當時的軟體授權（License）、版本與使用條件。本節只是研究規劃提醒，不構成法律意見。尚未完成授權與版本檢查前，不應進入實作或對外部署。

## 十八、階段計畫、資源、交付物與停止條件

### 18.1 階段計畫

本提案將後續工作分為九個階段：

1. **文件凍結**：完成研究提案、比較軸、標註結構規格與證據邊界。
2. **觀測契約原型**：定義 `AttentionCue`、`FocusRecord`、`TrackState`、`VisualEvent`、`InterpretationHypothesis`、`AttentionDirective`、`InteractionDecision` 的最小結構規格。
3. **先導錄影**：蒐集成年同意者的揮手、握手候選與高難度反例片段。
4. **`P0`–`P3` 感知比較**：建立感知／注意力軸的確定性比較基線（Deterministic Baseline）。
5. **`S0`–`S2` 語意比較**：在同一凍結事件串流上進行離線語意比較。
6. **`S3` 閉環比較**：使用配對情境種子與共享的指令生效前段，進行線上或重播式閉環配對比較。
7. **開發集分析與門檻凍結**：在開發集決定差距值、門檻值、TTL 與澄清政策。
8. **保留／測試資料驗證**：使用凍結設定執行配對評估，確認是否產生有界增益。
9. **整理交付物**：彙整報告、錯誤分類、設定紀錄與隱私安全的分享邊界。

文件完成只代表第 1 階段完成，不代表原型、資料集或實證結果（Empirical Result）已經存在。

### 18.2 資源假設

規劃中的最低資源包括：1 台固定 RGB 攝影機、可執行姿態估計／追蹤／手部標記點偵測的本機運算設備、成年志願參與者、標註工時、資料儲存空間與版本化紀錄機制。

人力至少需要一名系統開發者與兩名標註／裁決參與者。時間上暫定以數週完成先導研究與第一輪比較，但這只是排程假設，不是已承諾的完成時間。

### 18.3 交付物

每個階段都應產生明確交付物：

- 第 1 階段：研究提案與來源狀態交接文件（Source-status Handoff）。
- 第 2 階段：結構規格文件與驗證器（Validator）。
- 第 3 階段：附有同意紀錄與中繼資料（Metadata）的先導錄影。
- 第 4–6 階段：`P`／`S` 軸比較結果、錯誤分類、延遲／成本紀錄。
- 第 7–8 階段：凍結設定、配對評估報告與停止關卡結論。
- 第 9 階段：可供後續寫作或實作的整理報告，以及隱私安全釋出計畫。

### 18.4 有界成功準則與停止關卡

本提案不預先虛構達標數值，但允許在開發集分析後凍結差距值與門檻值，再以保留／測試資料關卡檢驗。研究停止或降級的條件至少包括：

- `P3 — attention-first` 相較於 `P2 — gesture-specific trigger` 沒有優勢，也沒有帕雷托效益（Pareto Benefit），例如效果相同但成本或焦點錯置率更低。
- `S3 — LLM attention feedback` 無法改善任何核心指標，或明顯增加焦點錯置、延遲、模型呼叫率或運算成本。
- 追蹤／可見性問題嚴重到 `P3` 幾乎無法穩定建立焦點。
- 無法滿足隱私、知情同意、資料保存期限或旁觀者保護的最低研究要求。

若觸發停止關卡（Stop Gate），研究應降級到較弱但更容易驗證的條件，例如停在 `P2＋S0` 或 `P3＋S0` 的比較；不能硬把失敗包裝成閉環成功。

## 十九、開放問題、待驗證來源與證據狀態

### 19.1 目前仍屬候選變數或工作假設的項目

動作、新奇性、朝向、預測誤差、任務相關性與不確定性，目前都只是候選注意力變數（Candidate Attention Variables）或工作假設（Working Hypotheses）。它們可以作為 `AttentionCue` 的設計輸入與消融對象，但不能在本提案中寫成已由一手文獻或本研究實驗證實的最佳注意力機制。

### 19.2 待進行的一手文獻驗證

下列主題仍需要一手文獻調查（Primary Literature Survey），才能支持更強的理論敘述：

- 主動感知（Active Perception）。
- 視覺顯著性（Visual Saliency）。
- 線上動作偵測（Online Action Detection）。
- 變化點偵測（Change-point Detection）。
- 預測誤差驅動的由上而下控制（Prediction-error Top-down Control）。
