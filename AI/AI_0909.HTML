現今 AI 技術發展迅速，各大科技巨頭紛紛推出其代表性的大型語言模型（LLM）。課堂中重點介紹了以下四款主流模型及其獨特優勢：

  • 關鍵優勢： 具備極長的上下文窗口（Long Context Window），邏輯推理能力強，並深度的整合 Google 產品生態系。

  • 關鍵優勢： 擅長程式碼生成、重構、自動補全與 Bug 診斷，為 GitHub Copilot 等先進 AI 編程助手提供強大動能。

開發團隊： Anthropic

  • 核心特色： 主打「憲法 AI (Constitutional AI)」與安全對齊（Alignment），強調負責任的 AI 發展。
  • 關鍵優勢： 文筆流暢自然、具備深度的長文本分析能力、複雜邏輯推理與嚴密的指令遵循（Instruction Following）能力。

開發團隊： xAI (Elon Musk)

  • 核心特色： 深入整合 X (Twitter) 社群平台的即時資料流，具備獨特的幽默感與直言不諱的性格設定。
  • 關鍵優勢： 能夠快速獲取當前最新的新聞動態與時事熱點，回應極具即時性與個性化。

單元三：AI.DEV 實驗平台實作 — System Prompts 設定

在實作環節中，使用 AI.DEV 實驗平台 進行了提示詞工程（Prompt Engineering）體驗，關鍵在於理解與設定 System Prompts。

1. 何謂 System Prompts（系統提示詞）？

System Prompt 是在使用者輸入訊息之前，優先載入給 AI 模型的全局最高指令。它定義了模型的「靈魂」、「角色背景」、「回答風格」、「遵守規範」以及「行為邊界」。

2. 角色與行為設定的核心架構

  • Role (角色設定)： 定義 AI 是誰，例如「資深 Python 架構師」、「親切的高中物理老師」。
  • Context (背景脈絡)： 提供必要的背景資訊或任務範疇。
  • Task (任務指示)： 明確指定 AI 需要執行的具體工作內容。
  • Constraints (限制條件)： 設定不可觸犯的禁忌或格式要求（如：簡體/繁體轉譯、限制字數、拒絕回答無關問題）。
  • Output Format (輸出格式)： 指定 Markdown, JSON, HTML 或表格回傳。

3. 實作範例 showcase

💻 實作範例一：設定「資深 Code Review 審查員」系統提示詞
[System Prompt] 你是一名擁有 15 年經驗的資深全棧軟體工程師。 你的任務是審查使用者提交的程式碼，並給出專業的改進建議。 請遵循以下行為準則： 1. 語氣：專業、嚴謹但具建設性。 2. 分析維度：包含效能優化 (Performance)、可讀性 (Readability)、安全性 (Security) 三大層面。 3. 格式要求： - 先指出 1~2 個優秀亮點。 - 再指出潛在 Bug 或待優化點，並附上改進前後的程式碼對比 (Diff)。 4. 如果使用者輸入的內容非程式碼，請禮貌引導其提供程式碼。
🎓 實作範例二：設定「耐心的 AI 互動教學導師」系統提示詞
[System Prompt] 你是 AI.DEV 平台的專屬學習導師「智小引」。 目標：引導初學者理解複雜的 AI 技術概念。 行為規範： - 禁止直接給出標準答案，必須採用「蘇格拉底提問法」引導思考。 - 使用生活中的比喻（例如將神經網路比喻為廚師作菜的調味料比例）。 - 每次回覆末尾必須附帶一個激發思考的小問題。

  1. 模型各有千秋： 沒有絕對最好的 AI 模型，Gemini 適合多模態與長文本分析，Codex 適合編程，Claude 擅長安全與精細文案，Grok 則擅長即時時事。選用正確的模型能事半功倍。

  3. 人機協作時代到来： 從傳統 AI 的「自動化執行」跨越到生成式 AI 的「協同創作」，工程師的角色的重點正從單純撰寫代碼轉變為問題定義、架構設計與 AI 控制調教。
