📖 1. GPT 生成原理、訓練過程與關鍵參數

GPT (Generative Pre-trained Transformer) 是由 OpenAI 開發的自迴歸語言模型。其核心設計思想是透過大規模無監督資料學習語言模式，再經由指令微調與人類偏好對齊，成為強大的通用文字與推理系統。

1.1 生成原理 (Generation Principles)

  • Decoder-Only 架構 GPT 採用僅解碼器 (Decoder-only) 的 Transformer 架構。與原始 Transformer 的 Encoder-Decoder 不同，GPT 只保留解碼層並使用「單向/遮罩注意力機制 (Masked Self-Attention)」，確保模型在預測當前詞彙時，只能看見之前的 Token，無法偷看未來的內容。
  • 自迴歸生成 (Auto-regressive Generation) 文本生成是逐步 (Step-by-step) 進行的。模型根據已生成的序列預測下一個 Token，將新生成的 Token 附加到末尾，再作為下一步的輸入：
P(w₁, w₂, ..., wₜ) = ∏ᵢ₌₁ᵗ P(wᵢ | w₁, w₂, ..., wᵢ₋₁)
[輸入 Prompt] ──> [Tokenization] ──> [Positional Encoding] │ ▼ [下一個 Token 採樣] <── [Softmax] <── [Transformer Block (Masked Attention)] │ └───> (附加至末尾，重複迴歸直到觸發 或達到長度限制)
  • Tokenization (詞元化) 採用 Byte Pair Encoding (BPE) 等演算法，將原始文字拆解為 Subword 詞元（例如文字 "Antigravity" 被拆為 "Anti" + "gravity"），有效控制字典大小並解決未登錄詞 (OOV) 問題。
  • 位置編碼 (Positional Encoding) 自注意力本身具備置換等變性（無法感知順序），因此需要引入位置資訊。GPT-2／GPT-3 使用可學習的絕對位置編碼；LLaMA 等許多開源 LLM 採用 RoPE (Rotary Position Embedding, 旋轉位置編碼)，提供相對位置資訊並便於擴展上下文長度（OpenAI 近期模型細節未公開）。

1.2 訓練過程 (Three-Stage Training Pipeline)

大型語言模型的訓練通常遵循經典的三階段流程：

階段一：無監督預訓練 (Pre-training)

資料集： 數萬億 (Trillions) Token 的網頁數據、書籍、學術論文、程式碼。

目標： 自監督下一個 Token 預測 (Next-Token Prediction)。

成果： 獲得世界知識、語法結構與基本推理能力，生成 Base Model。

階段二：監督微調 (SFT)

資料集： 數萬筆高質量的 (Prompt, Response) 指令對。

目標： 讓模型學會回答問題、遵守指令格式、扮演特定角色。

成果： 模型從單純續寫文章轉變為能進行問答互動的 SFT / Instruct Model。

階段三：人類反饋對齊 (Alignment Phase: RLHF & DPO)

單純的 SFT 容易產生幻覺 (Hallucination) 或有害言論，因此需要對齊人類價值觀 (Helpful, Honest, Harmless)：

  • RLHF (Reinforcement Learning from Human Feedback)：
    1. 收集人類偏好： 人類標註員對模型生成的同一個 Prompt 的多個回答進行排名。
    2. 訓練獎勵模型 (Reward Model, RM)： 學習人類偏好分數。
    3. 強化學習優化 (PPO 演算法)： 以 RM 分數作為獎勵，透過 Proximal Policy Optimization 調整 GPT 權重，同時加入 KL 散度懲罰防止模型偏離太遠。
  • DPO (Direct Preference Optimization, 直接偏好優化)： 2023年後極具代表性的創新。DPO 數學上證明了隱式獎勵函數與策略優化等價，可以直接在偏好數據集 (Prompt, Chosen_Answer, Rejected_Answer) 上優化模型，免去訓練獨立 RM 與 PPO 強化學習過程，大幅提升訓練穩定性。

1.3 模型關鍵參數解析 (Key Parameters)

參數類別 參數名稱 說明與作用機制
架構參數 模型參數量 (N) 權重總數（如 GPT-3 175B, GPT-4 參數量 OpenAI 未公開，外界流傳「約 1.8 兆參數 MoE」屬非官方推測）。決定模型的記憶與推理上限。
架構參數 隱藏維度 (dmodel) / 層數 (nlayer) 向量表徵的維度（如 4096, 8192）與 Transformer Block 堆疊層數（如 32, 80 層）。越高則抽象表徵能力越強。
推論參數 Temperature (溫度) 控制 Softmax 機率分佈的平滑度。T → 0 時極度確定、選擇最高機率詞彙（適用於數學/程式）；T > 0.7 時輸出多元富創造性。
推論參數 Top-p (Nucleus Sampling) 累積機率採樣。僅保留機率最高且累積和達 p (如 0.9) 的最小 Token 集合，剔除尾部低機率噪音。
推論參數 Context Window (上下文視窗) 模型單次推論能同時處理的最高 Token 數量（如 128k ~ 1M Token）。受限於注意力機制記憶體開銷（如 KV Cache）。

🎥 2. OpenAI Sora 影片生成原理

OpenAI 在 2024 年推出的 Sora 代表了影片生成技術的裡程碑。與過去基於 2D U-Net 的圖像擴散模型不同，Sora 將 Diffusion Transformer (DiT) 架構成功擴展至時空數據，實現了高達 60 秒的連續、高品質 1080p 影片生成。

[高維原始影片 (H×W×T)] ──> [3D Video VAE Encoder] ──> [時空 Latent 特徵] │ (壓縮空間與時間) ▼ [提示詞 Prompt] ──(GPT 擴寫 Prompt)──> [Text Token] ──> [DiT (Diffusion Transformer)] │ (時空 Patch 去噪) ▼ [去噪後 Latent 特徵] ──> [3D Video VAE Decoder] ──> [輸出 1080p 高清影片]

2.1 核心引擎：Diffusion Transformer (DiT)

傳統的 Video Diffusion 模型（如 Early Stable Video Diffusion）多使用 3D U-Net。但 U-Net 存在以下缺點：受限於卷積核的局部感受野，且難以有效發揮大模型算力的 Scaling Law (擴展法則)。

Sora 採用了由 William Peebles 和 Saining Xie 提出的 DiT 架構：

  • 將圖像/影片 Latent 轉化為一維 Token 序列，直接使用標準 Transformer 進行處理。
  • 實證證明：隨著訓練計算量 (Compute Cost) 的增加，DiT 的影片生成畫質與時空一致性明顯提升（技術報告以不同算力的樣本對比展示擴展效果）。

2.2 時空潛在塊 (Spatiotemporal Latent Patches)

Sora 能原生處理各種解析度 (1920x1080, 1080x1920)、長寬比與長度的影片，秘密在於 Visual Patches：

  • 統一的表徵： 文字模型將詞彙切為 Text Tokens，Sora 則將影片壓縮後的 Latent 數據在空間（高度 H、寬度 W）與時間（幀數 T）三個維度切分成小的 3D 塊（Patches）。
  • 靈活度： 不論影片是橫向、直向還是 short/long clip，全都被打碎為一連串 3D Patches 餵給 Transformer，免去了過去必須強行將影片裁切為 512x512 正方形的限制。

2.3 3D 影片壓縮網路 (3D Video Autoencoder / VAE)

原始 1080p 影片的像素數據量過於龐大，直接在像素空間進行擴散去噪極度消耗算力。Sora 訓練了一個高度壓縮的 3D VAE：

  • 雙重壓縮： 在空間層面（降採樣高寬）與時間層面（跨幀壓縮）進行維度縮減，將 RGB 像素對映至低維 Latent 空間。
  • 解碼還原： 當 DiT 完成去噪過程後，3D VAE Decoder 將生成的 Latent 數據解碼還原回連續的時空像素影片。

2.4 高精度文字重標註 (Recaptioning Technique)

為了使影片模型能精確聽懂複雜的 Prompt 指令，OpenAI 引入了在 DALL-E 3 驗證成功的 Recaptioning 技術：

  • 先訓練一個高度描述性的字幕模型（captioner），為訓練集中的影片生成 極度詳盡的描述（精確描述背景、人物動作、光影、鏡頭運鏡走向）。
  • 推論時，用戶輸入的簡短 Prompt 會先由 GPT 擴充為高細節描述，大幅改善文字與影片畫面內容的精確對齊。

🌟 Sora 湧現的物理世界模擬能力 (World Simulator Properties)

OpenAI 的技術報告指出，當算力規模擴大時，Sora 展現出了類似物理引擎的湧現能力：

  • 3D 空間一致性： 當鏡頭旋轉或移動時，場景中的物體與背景能維持精確的三維幾何關係。
  • 遮擋與物體持久性 (Object Permanence)： 人物或物體離開視線再重新出現時，外觀仍保持連貫。
  • 模擬世界互動： 畫家在畫布上留下筆觸、吃漢堡時留下咬痕等持久性的物理變化。

🚀 3. 目前最新的 AI 影片生成技術與模型剖析 (2024-2026)

截至 2026 年，AI 影片生成已從單純的實驗性展示邁入專業影視與廣告產線。全球主流技術已從單一純文字生成影片，全面演進為「多模態精確控管 + 原生聲畫同步 + 開源自建工作流」。

3.1 核心技術演進與突破趨勢

1. Flow Matching (流匹配採樣)

已成為許多新一代模型（如 SD3、FLUX 與多數新影片模型）的主流訓練框架。Flow Matching 透過建構較直的採樣路徑 (Straight ODE Trajectory)，能以較少的去噪步數生成高畫質影片，提升生成速度。

2. 3D Causal VAE (因果時空 VAE)

傳統 VAE 在時間軸上容易洩漏未來的資訊。3D Causal VAE 遵守時間因果性，只依賴當前與過去幀，有利於長影片的分段／流式 (Streaming) 生成。

3. 原生聲畫同步 (Native Audio Integration)

最新模型（如 Veo 3.1、Kling 3.0）不再只是生成無聲畫面，而是在 Latent 空間中同步解碼語音、音效與背景音樂，實現毫秒級口型對齊 (Lip-sync)。

4. 多圖控制與角色一致性 (Multi-Reference)

支援輸入 9+ 張角色與場景參考圖，結合姿態 (ControlNet)、軌跡引導 (Motion Trajectory)，徹底解決生成影片角色「變臉」的痛點。
