注意力優先閉環視覺互動系統

基於研究提案 (research_proposal_b02.md) 設計之四周紮實學習進度表與線上學習資源庫

🎯 核心技術：Computer Vision + LLM Closed-loop ⏱️ 課程週期：4 週 (28 天) 📍 實作對象：揮手 (Wave) / 握手歧義 (Handshake Candidate) 📄 參考文獻版本：b02
💡 計畫核心理念 (Attention-First)

傳統手勢辨識系統依賴「預設已知手勢類別」，而本計畫主張「先注意與聚焦，之後才形成事件名稱」。系統在未知事件名稱前，先利用動作、新奇性與姿態變化選擇焦點，累積跨影格證據後再形成可觀察事件與 LLM 互動決策。

🔄 雙時間尺度 (Fast / Slow Loop)

快速迴圈 (Fast Loop)：逐影格處理線索、焦點維持與追蹤，絕不因 LLM 延遲而阻塞。
慢速迴圈 (Slow Loop)：由視覺事件觸發 LLM 進行語意整合與文字決策，並回饋結構化指令 (AttentionDirective) 影響未來觀察。

📜 資料契約與證據不可變性

嚴格區分「視覺事件領域」(描述客觀事實，如手部週期動作) 與「綜合判斷領域」(假設與意圖推論)。所有歷史觀測紀錄 (VisualEvent) 採僅附加 (Append-only) 原則，禁止 LLM 改寫歷史觀測。

🔍 系統五大關鍵資料契約 (Data Contracts) 摘要：
連續影像影格 (RGB Frame) │ ▼ [1] AttentionCue (低階線索: 動作/新奇性/預測誤差/朝向，不預設事件名稱) │ ▼ [2] FocusRecord & TrackState (注意力排序/維持/切換/遲滯管理 + 跨影格目標軌跡) │ ▼ [3] VisualEvent (累積時序證據: periodic_hand_motion / arm_extension) │ ├───> [4] InterpretationHypothesis (語意整合: S0確定性規則 / S1-S3 LLM語意推測) │ │ │ ├───> [5] InteractionDecision (文字決策: respond / clarify / wait / no_response) │ │ └────────└───> [6] AttentionDirective (Top-down 回饋指令: 指定未來觀察焦點與時效 TTL)

第 1 週：基礎視覺感知、人體姿態估計與注意力線索提取 (Attention Cue Extraction)

學習目標：掌握固定 RGB 攝影機的影像處理基礎、姿態與手部關鍵點偵測（YOLO / MediaPipe），並實現無語意標籤的低階注意力線索生成機制（AttentionCue）。

Day 1 - Day 2

固定 RGB 視覺基礎與 OpenCV/MediaPipe 環境搭建

  • 熟悉固定視角的視覺擷取管線、影像串流處理與影格率 (FPS) 控制。
  • 學習使用 MediaPipe Holistic / Pose / Hands 或 YOLOv8/v11-Pose 進行即時人體姿態與手部關鍵點標記。
  • 建立數據結構傳遞單影格關鍵點座標、信心度與邊界框 (Bounding Box)。
🛠️ 推薦資源： MediaPipe 官方文件 | Ultralytics YOLO Pose 文件
Day 3 - Day 4

低階視覺特徵與一般性注意力線索 (Generic Attention Cues) 計算

  • 實作光流法 (Optical Flow) 或前後影格差異 (Frame Differencing) 計算局部動作強度 (Motion Intensity)。
  • 計算特徵區域的空間新奇性 (Novelty) 與預測誤差 (Prediction Error)。
  • 設計不依賴手勢類別名稱的 AttentionCue 資料結構（包含 cue_id, strength, spatial_extent, cue_type）。
📖 重點閱讀概念： Visual Saliency (視覺顯著性)、Motion Salience、Optical Flow (Farneback算法)。
Day 5 - Day 7

實作 Lab 1：無預設標籤的 AttentionCue 產生器與單元測試

編寫 Python 模組：從鏡頭讀取影像，當畫面上出現顯著運動或區域變化時，生成 AttentionCue 物件，並以繪圖方式顯示於畫面中，嚴禁將其標記為 "wave" 或 "handshake"。

# 範例數據格式：AttentionCue
{
    "cue_id": "cue_20260901_001",
    "observed_at": "2026-09-01T10:00:00.120Z",
    "cue_type": "motion_burst",
    "strength": 0.85,
    "spatial_extent": {"x_min": 0.3, "y_min": 0.2, "x_max": 0.5, "y_max": 0.6},
    "measurement_quality": 0.92
}

第 2 週：跨影格目標追蹤、注意力管理與時序事件形成 (Temporal Event Formation)

學習目標：掌握多目標追蹤 (MOT)、遲滯與最短停留時間機制，設計注意力管理器 (Attention Manager) 並將跨影格變化轉化為 VisualEvent。

Day 8 - Day 10

跨影格多目標追蹤 (Multi-Object Tracking) 與 TrackState 維持

  • 學習卡爾曼波波器 (Kalman Filter) 與 Hungarian 演算法在目標關聯中的應用。
  • 使用 ByteTrack / DeepSORT 管理跨影格目標，建立 TrackState。
  • 處理短暫遮擋 (Occlusion) 寬限期，確保目標消失時不會無限猜測，重新出現時建立新軌跡。
🛠️ 推薦資源： ByteTrack GitHub 庫 | ByteTrack Paper
Day 11 - Day 12

注意力管理器 (Attention Manager) 排序與遲滯 (Hysteresis) 機制

  • 設計注意力排序演算法：結合線索強度、時間持續度與任務權重。
  • 引入遲滯 (Hysteresis)、切換成本 (Switching Cost) 與 最短停留時間 (Minimum Dwell Time)，防止焦點劇烈抖動。
  • 輸出 FocusRecord 記錄焦點選擇、維持與切換決策。
Day 13 - Day 14

實作 Lab 2：時序事件形成器 (VisualEvent Extractor)

從持續聚焦的影格軌跡中，累積時序特徵並發布客觀可觀察事件 VisualEvent（如 periodic_hand_motion_above_torso 或 arm_extension_open_palm）。

# 範例數據格式：VisualEvent (嚴禁使用 wants_handshake 作為 event_type)
{
    "visual_event_id": "evt_wave_001",
    "event_type": "periodic_hand_motion_above_torso",
    "start_at": "2026-09-01T10:00:01.000Z",
    "end_at": "2026-09-01T10:00:03.500Z",
    "temporal_pattern": "frequency_2.5hz_duration_2500ms",
    "observation_quality": 0.88
}

第 3 週：雙時間尺度架構、確定性基線與 LLM 閉環回饋機制 (Closed-Loop Feedback)

學習目標：理解 Fast/Slow Loop 解耦架構，實作 S0 確定性狀態機基線，並透過 Pydantic / JSON Schema 實作 LLM 結構化語意推論與 Top-down 注意力回饋（AttentionDirective）。

Day 15 - Day 17

Fast Loop 與 Slow Loop 解耦架構 & S0 確定性基線實作

  • 實作雙時間尺度架構：快速迴圈 (30 FPS) 不同步等待 LLM 回覆，確保不卡頓。
  • 設計 S0 (Deterministic Baseline)：透過品質閘門 (Quality Gate)、狀態機與衝突路由器 (Conflict Router)，在無 LLM 下輸出確定性回應 (白名單式回應)。
  • 針對 arm_extension_open_palm 事件，路由器同時保留 handshake_candidate, object_reach, object_pass 等競態假設。
Day 18 - Day 19

LLM 結構化輸出 (Structured Outputs) 與 InterpretationHypothesis

  • 使用 Pydantic 或 Instructor API 限制 LLM 輸出為 JSON Schema 格式。
  • 生成 InterpretationHypothesis，要求 LLM 保留不確定性與替代解釋。
  • 設計 S1 (自然語言擴充) 與 S2 (歧義澄清問答)。
🛠️ 推薦工具： Pydantic 文件 | Instructor Python Library
Day 20 - Day 21

實作 Lab 3：S3 閉環注意力指令 (AttentionDirective) 回傳與降級處理

當語意層缺少區分假設的證據時（例如無法判定是握手還是取物），產生有時效性 (TTL) 的 AttentionDirective 給快速迴圈，指定提升特定目標區域的觀測優先度。若 LLM 逾時或格式錯誤，自動安全降級為 S0。

# 範例數據格式：AttentionDirective (Top-down 回饋)
{
    "directive_id": "dir_focus_hand_001",
    "issued_at": "2026-09-01T10:00:04.000Z",
    "target": {"track_id": "track_person_02"},
    "watch": "hand_to_object_distance_change",
    "reason": "distinguish_handshake_vs_object_reach",
    "ttl": 3.0,  # 3秒後自動失效
    "priority": 0.8
}

第 4 週：端到端系統整合、消融實驗比較與客觀評估指標 (Evaluation & Ablation)

學習目標：完成 P0-P3 感知軸與 S0-S3 語意軸的消融矩陣實驗，錄製包含高難度反例 (Hard Negatives) 的測試資料，執行端到端性能評估與失敗歸因分析。

Day 22 - Day 24

測試場景設計與高難度反例 (Hard Negatives) 資料集採集

  • 錄製 3 大類測試影片：(1) 正確揮手打招呼 (2) 歧義伸手握手 (3) 高難度反例。
  • 高難度反例涵蓋：調整眼鏡、抓癢、摸頭、指向、伸手取物、遞物、對旁人揮手、多人交錯與背景干擾。
  • 標註六大層級：影格、追蹤軌跡、焦點區間、視覺事件、解讀與決策。
Day 25 - Day 26

消融實驗 (Ablation Study) 矩陣執行

感知 / 注意力軸 (P) 語意控制軸 (S) 評估重點與比較假設
P0 — single-frame S0 — deterministic 單影格無記憶基線 vs 時間記憶必要性 (H1 驗證)
P2 — gesture-specific S0 — deterministic 手勢專屬觸發 vs 注意力優先 P3 的聚焦延遲 (H2 驗證)
P3 — attention-first S0 / S1 / S2 在相同凍結事件串流下，離線比較 LLM 澄清與確定性規則 (H4 驗證)
P3 — attention-first S3 — LLM feedback 配對情境種子下的閉環比較，驗證語意回饋是否帶來真實效益 (H5 驗證)
Day 27 - Day 28

實作 Lab 4：評估報表生成與 Stop Gate (停止關卡) 判斷

計算核心指標：Time to Focus (聚焦延遲), Event F1 Score, False Activations (誤觸發率), ID Switches, Fast/Slow Loop Latency 與 Model Compute Cost。進行失敗歸因 (Failure Attribution)，並依提案第 18.4 節進行 Stop Gate 審查。
